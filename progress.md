# Журнал решений — analytics-gym

Хронология значимых решений и открытых вопросов. Новые записи сверху.

## 2026-08-02 — старт проекта, этапы 0–3

### Решения

**Full-stack, а не статический сайт.** Рассматривались три варианта: Markdown + статика на Pages,
full-stack как в `language-app`, гибрид со Supabase. Выбран full-stack: нужна нормальная аналитика
по своей активности и удобная работа с прогрессом. Плата за это — деплой не бесплатный, поэтому
основной режим локальный.

**Контент в Markdown, а не в БД.** При full-stack источником правды всё равно оставлены файлы
`content/**/*.md`, а `sync` делает upsert в Postgres. Причины: контент виден в публичном репо (это
и есть портфолио), правится в редакторе и с github.com, лежит в git-истории. БД можно снести и
пересобрать за секунды. Персональные данные при этом живут только в БД.

**PGlite вместо DuckDB-WASM и sql.js.** Диалект должен быть один в один с боевым Postgres, иначе
отработанные решения не переносятся на собеседование. PGlite — настоящий Postgres в WASM (~3.7 МБ
gzip). Грузится лениво, только на страницах SQL-задач.

**Эталонный результат пересчитывается, а не хранится.** Вместо захардкоженного ожидаемого вывода
при каждой проверке выполняется эталонный SQL из задачи на том же датасете. Правка датасета
перестаёт ломать все задачи, которые на нём построены.

**Абстракция `DataSource` заложена сразу.** Приложение работает с FastAPI локально и как статичное
демо на Pages. Интерфейс с двумя реализациями закладывается до написания страниц, иначе позже
пришлось бы переписывать весь UI.

**`tools/` внутри backend, а не в корне.** CLI переиспользует ORM-модели, настройки и сессию
бэкенда. Отдельный uv-проект в корне означал бы дублирование зависимостей и второй venv.

**`validate` выполняет эталонные SQL на живом Postgres.** Не только проверка frontmatter: каждое
решение реально прогоняется поверх своего датасета. Ошибка ловится при написании задачи, а не
через месяц при повторении.

**SM-2 продублирован на Python и TypeScript.** Осознанный компромисс: логика нужна и на бэкенде, и
в статическом демо. Реализации держатся синхронными общими тест-кейсами. Альтернатива (демо без
повторений) хуже для витрины.

**Порт Postgres 5433.** 5432 занят соседним проектом `language-app`.

**Своя тема подсветки в редакторе вместо готовой.** Тёмные темы CodeMirror задают цвета
абсолютными значениями под свой фон: на нашей подложке ключевые слова оказались темнее
обычного текста и читались хуже него. Подсветка переведена на CSS-переменные приложения
(`editor-theme.ts`), редактор перекрашивается вместе со всем остальным из `index.css`.

**В демо на Pages — HashRouter и абсолютный base.** Два бага, найденных прогоном демо-сборки
в браузере: при относительном `base: './'` запрос `content.json` со страницы `/t/slug` уходил
в `/t/content.json`, а Pages не умеет отдавать `index.html` на произвольный путь. Поэтому
демо собирается с базой `/analytics-gym/` (переопределяется через `VITE_BASE`) и использует
хеш-маршруты. Локальный режим остался на обычных адресах.

**Postgres на 5433, Docker не потребовался.** На машине не оказалось Docker, зато есть
`postgresql@16` из brew. Кластер поднят на 5433 командой `pg_ctl` (без регистрации автозапуска
через `brew services`), база и роль `analytics_gym` созданы. `docker-compose.yml` оставлен для
переносимости. На macOS кластеру нужна явная локаль, иначе он падает с
`postmaster became multithreaded during startup`.

**Логика статусов вынесена из репозитория в services.** Правило «из solved не откатываемся»
лежало в data-слое, что противоречит слоистости. Теперь это чистые функции в
`services/progress.py` с юнит-тестами, а репозиторий только сохраняет посчитанное состояние.

### Открытые вопросы
- Шрифт: Inter или Golos Text — решить, когда будет наполнен контент и станет видно, как читается кириллица.
- Нужен ли режим «сессия на 30 минут» (подборка задач под таймер) — вернуться после первого месяца использования.
- Создание публичного репозитория на GitHub — отложено до явного подтверждения владельца.
