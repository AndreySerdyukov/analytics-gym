## Что ты будешь уметь после этого урока

- мгновенно выбирать между list, dict и set, понимая почему;
- объяснять, почему поиск в множестве в тысячи раз быстрее, чем в списке;
- знать, какие инструменты стандартной библиотеки закрывают типовые задачи;
- не писать O(N²) там, где должно быть O(N).

## Главная идея

Начинающие думают о структурах данных так: «это разные способы хранить данные». Из-за этого
выбор кажется вкусовщиной – какая разница, положу я числа в список или в множество?

Правильная модель другая:

> **Структура данных – это не способ хранить. Это способ быстро отвечать на конкретный вопрос.**

Каждая структура умеет отвечать мгновенно на **свой** вопрос и медленно на все остальные.
Поэтому выбор делается так: **посмотри, какой вопрос ты будешь задавать чаще всего, и возьми
структуру, которая отвечает на него за O(1).**

### Таблица выбора

Это главная таблица конспекта. Если запомнить только её, конспект уже окупился.

| Вопрос, который ты задаёшь чаще всего | Структура |
|---|---|
| «дай элемент номер i», «мне важен порядок» | **list** |
| «встречался ли уже такой элемент?» | **set** |
| «что связано с этим ключом?» | **dict** |
| «сколько раз встретился каждый элемент?» | **Counter** |
| «сгруппируй элементы по признаку» | **defaultdict(list)** |
| «кто следующий в очереди?» (первым пришёл, первым вышел) | **deque** |
| «кто зашёл последним?» (стек, LIFO) | **list** (`append` / `pop`) |
| «какой сейчас минимум / максимум?» из меняющегося набора | **heapq** |
| «куда вставить, чтобы порядок сохранился?» | **bisect** |
| «нужен ключ словаря из нескольких значений» | **tuple** |
| «нужно множество как элемент другого множества» | **frozenset** |

### Три вопроса для выбора

Если таблица не подошла, спроси себя по порядку:

**1. Мне важен порядок элементов или доступ по номеру?**
Да – `list`. Нет – идём дальше.

**2. Мне нужно хранить что-то вместе с элементом (значение по ключу)?**
Да – `dict`. Нет, нужен только факт наличия – `set`.

**3. Мне нужны дубликаты?**
Да – `list` (или `Counter`, если важно только количество). Нет – `set`.

### Аналогия из аналитики

Ты каждый день работаешь с данными, и у каждой структуры есть точный аналог:

| Структура | Аналог из мира данных |
|---|---|
| `list` | столбец таблицы: есть порядок строк, обращаются по номеру строки |
| `dict` | справочник для join: по ключу мгновенно достаётся запись. Это `VLOOKUP` или `LEFT JOIN` |
| `set` | результат `SELECT DISTINCT` плюс проверка `WHERE x IN (...)` |
| `Counter` | `GROUP BY x COUNT(*)` |
| `defaultdict(list)` | `GROUP BY` с агрегацией строк в список |
| `heapq` | `ORDER BY … LIMIT k`, но работающий на потоке, без полной сортировки |
| `deque` | очередь сообщений: пришло в конец, обработали с начала |

Если держать эту таблицу в голове, выбор структуры перестаёт быть загадкой.

## Почему dict и set такие быстрые

Это ключ ко всему конспекту. Понимание механизма избавляет от необходимости заучивать таблицы
сложностей.

### Как ищет список

Список – это последовательность ячеек в памяти. Когда ты пишешь `x in arr`, Python **честно
перебирает элементы по порядку**, пока не найдёт совпадение.

```
arr = [17, 4, 92, 8, 33]
"есть ли 33?" → сравнить с 17 → с 4 → с 92 → с 8 → с 33 → нашли
```

Пять элементов – до пяти сравнений. Миллион элементов – до миллиона сравнений. Это **O(N)**.

### Как ищет множество

Множество не хранит элементы подряд. Оно берёт элемент, считает от него **хеш** – число,
полученное детерминированным преобразованием, – и по этому числу определяет **номер ячейки**,
куда положить элемент.

```
x = 33
hash(33) → какое-то число → номер ячейки, скажем 7
кладём 33 в ячейку 7
```

Когда ты спрашиваешь «есть ли 33?», Python **не перебирает ничего**. Он снова считает
`hash(33)`, получает ту же ячейку 7 и смотрит только туда.

```
"есть ли 33?" → hash(33) → ячейка 7 → смотрим: да, лежит
```

Один шаг вместо миллиона. Это **O(1)**.

Ключевой момент: время не зависит от размера множества. В множестве из десяти элементов
и из десяти миллионов поиск занимает одинаковое время.

### Сколько это в реальных цифрах

Замер: 1000 проверок «есть ли элемент», коллекция разного размера.

| Размер коллекции | `x in list` | `x in set` | Разница |
|---|---|---|---|
| 1 000 | 7,4 мс | 0,057 мс | в 130 раз |
| 10 000 | 60 мс | 0,15 мс | в 390 раз |
| 100 000 | 512 мс | 0,14 мс | **в 3700 раз** |

Обрати внимание на две вещи:

1. Время для списка растёт пропорционально размеру – это и есть O(N).
2. Время для множества **не растёт вообще** – это O(1).

Практический пример: убрать дубликаты из 10 000 элементов.

| Способ | Время |
|---|---|
| `if x not in result` (список) | 153 мс |
| `if x in seen` (множество) | 1,0 мс |

На 100 000 элементов вариант со списком просто не дождаться, а вариант с множеством
отрабатывает за 21 мс.

**Вывод, который стоит запомнить дословно:** если ты внутри цикла проверяешь принадлежность –
это должно быть множество или словарь, никогда не список. Эта одна замена превращает O(N²)
в O(N) и решает половину задач уровня medium.

### Чем платим

Скорость не бесплатна. У хеш-таблиц три ограничения:

**1. Элементы должны быть хешируемыми.** То есть неизменяемыми: числа, строки, кортежи,
`frozenset`. Список в множество не положить.

```python
seen = set()
seen.add((1, 2))        # ✅ кортеж
seen.add([1, 2])        # ❌ TypeError: unhashable type: 'list'
```

**2. Больше памяти.** Хеш-таблица держит запас пустых ячеек, чтобы коллизии были редкими.
Множество из N чисел занимает примерно вчетверо больше, чем список из тех же чисел.

**3. Множество не хранит порядок.** Если порядок важен – либо список, либо словарь (он
с версии 3.7 сохраняет порядок вставки).

**4. Нет доступа по индексу.** `s[0]` для множества не работает – в нём нет «нулевого» элемента.

### Оговорка про худший случай

Формально `x in set` – это O(1) **в среднем**. Если у всех элементов совпадут хеши, они
соберутся в одной ячейке, и поиск выродится в перебор, то есть O(N). На практике этого
не происходит.

Правильный ответ на собеседовании: **«O(1) в среднем; в теории худший случай O(N) при массовых
коллизиях, но на реальных данных это не встречается»**.

## list – когда важен порядок

**Что это по сути.** Упорядоченная последовательность с доступом по номеру. Внутри – массив
указателей, лежащих подряд в памяти.

**На какой вопрос отвечает мгновенно:** «дай элемент номер i», «добавь в конец», «забери
с конца», «сколько всего элементов».

| Операция | Сложность | Комментарий |
|---|---|---|
| `arr[i]`, `arr[i] = x` | O(1) | это его главное умение |
| `len(arr)` | O(1) | длина хранится готовой |
| `arr.append(x)` | O(1) амортизированно | |
| `arr.pop()` | O(1) | с конца |
| `arr.pop(0)` | **O(N)** | ⚠️ сдвигает весь список |
| `arr.insert(i, x)` | **O(N)** | ⚠️ |
| `arr.remove(x)` | **O(N)** | ⚠️ ищет, потом сдвигает |
| `x in arr` | **O(N)** | ⚠️ самая частая ловушка |
| `arr.index(x)` | **O(N)** | ⚠️ |
| `arr[a:b]` | O(b−a) | ⚠️ всегда копирует |
| `arr.sort()` | O(N log N) | |
| `min`, `max`, `sum` | O(N) | ⚠️ внутри цикла = O(N²) |

**Когда брать:** нужен порядок; нужен доступ по индексу; нужны дубликаты; нужен **стек**
(`append` кладёт, `pop` снимает, обе операции O(1)); нужна таблица ДП.

**Когда НЕ брать:**

- **если основная операция это поиск** – бери `set` или `dict`
- **если нужна очередь** (добавлять в конец, брать с начала) – бери `deque`, потому что
  `pop(0)` это O(N)
- если нужно часто вставлять в середину

**Где встречается в алгоритмах.** Таблицы ДП, стек (в том числе монотонный), массив
результатов, куча через `heapq` (она живёт в обычном списке), путь в backtracking.

```python
# list как стек – одна из самых частых конструкций
stack = []
for ch in s:
    if ch == '(':
        stack.append(ch)
    elif ch == ')':
        if not stack:
            return False
        stack.pop()
return not stack
```

## dict – когда нужно соответствие ключ → значение

**Что это по сути.** Хеш-таблица: по ключу мгновенно достаётся связанное с ним значение.

**На какой вопрос отвечает мгновенно:** «что связано с этим ключом?», «есть ли такой ключ?»,
«запомни: этому ключу соответствует это значение».

| Операция | Сложность |
|---|---|
| `d[key]`, `d[key] = v`, `del d[key]` | O(1) в среднем |
| `key in d` | O(1) в среднем |
| `len(d)` | O(1) |
| `d.get(key, default)` | O(1) |
| перебор `for k in d` | O(N) |
| `d.keys()`, `d.values()`, `d.items()` | O(1) на создание представления |

**Когда брать.** Ключевой признак: **тебе мало знать, что элемент был – нужно помнить что-то
про него.**

- «где я видел этот элемент» – `значение: индекс`
- «сколько раз встретился» – `значение: счётчик`
- «какие элементы попали в эту группу» – `значение: список`
- граф: `вершина: список соседей`
- кеш / мемоизация: `аргументы: результат`

**Когда НЕ брать:** если значение не нужно, а нужен только факт наличия – возьми `set`,
он экономнее и честнее выражает намерение; если нужен порядок по значению, а не по вставке –
сортируй отдельно.

### Порядок в словаре

Начиная с Python 3.7 словарь **гарантированно сохраняет порядок вставки**. Это удобно и на это
можно опираться. Но это порядок добавления, а не сортировка.

```python
d = {}
d["b"] = 1
d["a"] = 2
list(d)              # ['b', 'a'] – порядок вставки, не алфавитный
```

### Полезные приёмы

```python
d.get(key, 0)                    # значение или дефолт, без KeyError
d.setdefault(key, []).append(x)  # создать список, если ключа нет

# перебор пар
for key, value in d.items():
    ...

# найти ключ с максимальным значением
best = max(d, key=d.get)

# отсортировать словарь по значению
for k, v in sorted(d.items(), key=lambda kv: -kv[1]):
    ...

# инвертировать словарь
inverted = {v: k for k, v in d.items()}
```

**Где встречается в алгоритмах.** Two Sum (значение → индекс), подсчёт частот, группировка,
список смежности графа, мемоизация ДП, LRU-кеш, префиксные суммы с хешом.

```python
# Классика: значение -> индекс
def two_sum(nums, target):
    index_of = {}
    for i, x in enumerate(nums):
        need = target - x
        if need in index_of:
            return [index_of[need], i]
        index_of[x] = i
    return []
```

## set – когда важен только факт наличия

**Что это по сути.** Тот же самый механизм, что у словаря, но без значений. **Множество –
это словарь, у которого есть только ключи.**

**На какой вопрос отвечает мгновенно:** «встречался ли уже такой элемент?», «добавь, если ещё
не было», «сколько различных элементов?».

| Операция | Сложность |
|---|---|
| `s.add(x)`, `s.remove(x)`, `x in s` | O(1) в среднем |
| `s.discard(x)` | O(1), не падает если элемента нет |
| `len(s)` | O(1) |
| `s1 & s2` (пересечение) | O(min(len(s1), len(s2))) |
| `s1 \| s2` (объединение) | O(len(s1) + len(s2)) |
| `s1 - s2` (разность) | O(len(s1)) |
| `s1 <= s2` (подмножество) | O(len(s1)) |

**Когда брать:** проверка «было ли уже» – главный сценарий; убрать дубликаты `set(arr)`;
`visited` в обходе графа или сетки; пересечение, объединение, разность коллекций; «сколько
уникальных значений» – `len(set(arr))`.

**Когда НЕ брать:** если нужен порядок; если нужны дубликаты; если нужно хранить что-то помимо
самого факта (тогда `dict`); если элементов мало (скажем, меньше десяти) – разница со списком
незаметна, а `list` читаемее.

### Операции над множествами

Это то, чего нет ни у списка, ни у словаря, и в задачах на «общие элементы» экономит кучу кода:

```python
a = {1, 2, 3, 4}
b = {3, 4, 5}

a & b        # {3, 4}        – общие
a | b        # {1,2,3,4,5}   – все
a - b        # {1, 2}        – только в a
a ^ b        # {1, 2, 5}     – только в одном из них
a.isdisjoint(b)   # False    – пересекаются ли вообще
```

**Где встречается в алгоритмах.** `visited` в BFS/DFS, скользящее окно без повторов,
Contains Duplicate, Longest Consecutive Sequence, пересечения массивов.

```python
# Множество как visited в обходе сетки
visited = set()
visited.add((r, c))              # кортеж, потому что список нехешируем
if (nr, nc) not in visited:
    ...
```

### Мини-разбор: list или set?

```python
# ❌ O(N²) – проверка принадлежности в списке
def dedupe(arr):
    result = []
    for x in arr:
        if x not in result:      # O(len(result))
            result.append(x)
    return result

# ✅ O(N) – проверка в множестве, порядок сохраняем списком
def dedupe(arr):
    seen = set()
    result = []
    for x in arr:
        if x in seen:
            continue
        seen.add(x)
        result.append(x)
    return result
```

Заметь: здесь нужны **обе** структуры. Множество отвечает на вопрос «было ли», список хранит
порядок. Это очень частая связка – не думай, что надо выбрать что-то одно.

## tuple – неизменяемая связка

**Что это по сути.** Список, который нельзя менять. Из-за неизменяемости он **хешируемый**,
и это его главная суперсила.

| Ситуация | Почему кортеж |
|---|---|
| Ключ словаря / элемент множества | список нехешируем, кортеж хешируем |
| Координаты клетки `(r, c)` | компактно и можно класть в `visited` |
| Возврат нескольких значений из функции | `return lo, hi` |
| Элемент кучи с приоритетом | `(priority, value)` |
| Аргумент мемоизированной функции | `@lru_cache` требует хешируемости |

### Суперсила: лексикографическое сравнение

Кортежи сравниваются поэлементно, слева направо:

```python
(1, 5) < (2, 0)    # True – сравнивает первые элементы
(1, 5) < (1, 9)    # True – первые равны, сравнивает вторые
```

Отсюда бесплатная многокритериальная сортировка:

```python
intervals.sort()                       # по началу, при равенстве по концу
heapq.heappush(heap, (dist, node))     # куча по dist, при равенстве по node
words.sort(key=lambda w: (len(w), w))  # по длине, потом по алфавиту
```

### Ловушка

Кортеж неизменяем **поверхностно**. Если внутри лежит список, кортеж перестаёт быть хешируемым:

```python
hash((1, 2))       # ✅
hash((1, [2]))     # ❌ TypeError
```

Подробности – в предыдущем конспекте темы, в разделе про хешируемость.

## deque – когда нужна очередь

**Что это по сути.** Двусторонняя очередь: добавление и удаление с **обоих концов** за O(1).

```python
from collections import deque
```

**Зачем она нужна.** У списка `pop(0)` стоит O(N), потому что все элементы приходится сдвигать
влево. Если делать так в цикле, алгоритм становится квадратичным.

**Реальный замер**, обработка очереди из 100 000 элементов:

| Способ | Время |
|---|---|
| `list.pop(0)` | 932 мс |
| `deque.popleft()` | **5 мс** |

Разница в 186 раз. И она растёт с размером данных.

| Операция | Сложность |
|---|---|
| `dq.append(x)`, `dq.pop()` | O(1) |
| `dq.appendleft(x)`, `dq.popleft()` | O(1) |
| `dq[0]`, `dq[-1]` | O(1) |
| `dq[len(dq)//2]` | **O(N)** ⚠️ доступ к середине медленный |
| `len(dq)` | O(1) |

**Когда брать:** **BFS** – всегда, это главное применение; любая обработка «первым пришёл,
первым вышел»; скользящее окно, где нужно выкидывать элементы слева (монотонная очередь);
когда нужен буфер фиксированной длины – `deque(maxlen=k)` сам выталкивает старые элементы.

**Когда НЕ брать:** если нужен произвольный доступ по индексу – бери список; для стека `deque`
не нужен: у списка `append` и `pop` и так O(1).

```python
from collections import deque

def bfs(start, graph):
    queue = deque([start])          # ← не list!
    visited = {start}
    while queue:
        node = queue.popleft()      # O(1)
        for nb in graph[node]:
            if nb not in visited:
                visited.add(nb)
                queue.append(nb)
```

## heapq – когда нужен минимум из меняющегося набора

**Что это по сути.** Куча (приоритетная очередь). Держит набор элементов так, что **минимальный
доступен мгновенно**, а вставка и извлечение стоят O(log N). В Python куча живёт прямо в обычном
списке, отдельного типа нет.

**Зачем она нужна.** Если минимум нужен один раз – просто вызови `min(arr)`, это O(N). Куча
нужна, когда **набор постоянно меняется**, и минимум нужен многократно. Сортировать заново
каждый раз – O(N log N) на каждый запрос, куча даёт O(log N).

Второй сценарий – **поток данных**: элементы приходят по одному, все сразу недоступны, а нужно
всё время держать топ-K.

| Операция | Сложность |
|---|---|
| `heapq.heappush(h, x)` | O(log N) |
| `heapq.heappop(h)` | O(log N) – извлечь минимум |
| `h[0]` | O(1) – посмотреть минимум без извлечения |
| `heapq.heapify(arr)` | **O(N)** – превратить список в кучу на месте |
| `heapq.nlargest(k, arr)` | O(N log k) |

Обрати внимание на `heapify`: построить кучу из готового списка стоит O(N), а не O(N log N).
Если все данные уже есть – всегда `heapify`, а не N вызовов `heappush`.

### Два обязательных приёма

**Max-heap через минус.** В Python куча всегда минимальная:

```python
h = []
for x in [5, 1, 3]:
    heapq.heappush(h, -x)
largest = -heapq.heappop(h)   # 5
```

**Пары (приоритет, значение)** – кортежи сравниваются лексикографически:

```python
heapq.heappush(h, (2, "task_b"))
heapq.heappush(h, (1, "task_a"))
heapq.heappop(h)     # (1, 'task_a')
```

⚠️ Если приоритеты равны, Python начнёт сравнивать вторые элементы. Если это несравнимые
объекты – `TypeError`. Лечится счётчиком-тайбрейкером: `(priority, counter, obj)`.

**Когда брать:** «K-й наибольший / наименьший», «топ-K»; задачи на поток данных, медиана потока
(две кучи); слияние нескольких отсортированных источников; планировщик задач по приоритету;
алгоритм Дейкстры.

**Когда НЕ брать:** если нужно отсортировать всё один раз – просто `sorted()`, это проще
и быстрее; если нужен доступ к произвольному элементу – куча этого не умеет; если K близко
к N – проще отсортировать.

### Мнемоника, которая всегда путается

Для K **наибольших** используем **min**-heap размера K. Для K **наименьших** – **max**-heap.

Кажется наоборот, но логика такая: куча должна быстро отдавать **худшего из тех, кого мы
держим**, чтобы вытеснить его новым кандидатом.

```python
def k_largest(nums, k):
    heap = []                        # min-heap размера k
    for x in nums:
        heapq.heappush(heap, x)
        if len(heap) > k:
            heapq.heappop(heap)      # выкидываем наименьший
    return heap                      # остались k наибольших
```

## Counter и defaultdict – словари со суперспособностями

Оба живут в модуле `collections` и оба – просто удобные обёртки над `dict`.

### Counter – подсчёт частот

```python
from collections import Counter

c = Counter("aabbbc")
# Counter({'b': 3, 'a': 2, 'c': 1})

c['b']              # 3
c['z']              # 0 – не KeyError!
c.most_common(2)    # [('b', 3), ('a', 2)]
```

Главное умение – сравнение и арифметика:

```python
Counter("listen") == Counter("silent")   # True – проверка на анаграммы за O(N)

c1, c2 = Counter("aab"), Counter("abc")
c1 - c2             # Counter({'a': 1}) – только положительные остатки
c1 & c2             # Counter({'a': 1, 'b': 1}) – поэлементные минимумы
```

**Когда брать:** анаграммы, частоты, «самый частый элемент», скользящее окно по строкам, любые
задачи, где в SQL ты написал бы `GROUP BY … COUNT(*)`.

### defaultdict – словарь без KeyError

Обычный словарь падает, если ключа нет. `defaultdict` создаёт значение по умолчанию
автоматически.

```python
from collections import defaultdict

graph = defaultdict(list)
graph[1].append(2)       # ключа 1 нет – создаётся пустой список

count = defaultdict(int)
count[ch] += 1           # начнётся с нуля

groups = defaultdict(set)
groups["a"].add(1)
```

**Когда брать:** группировка, построение графа, накопление – всё, где ты иначе писал бы
`if key not in d: d[key] = []`.

```python
# Построение графа из списка рёбер – стандартная заготовка
graph = defaultdict(list)
for u, v in edges:
    graph[u].append(v)
    graph[v].append(u)   # для неориентированного
```

```python
# Группировка анаграмм
groups = defaultdict(list)
for word in words:
    groups[tuple(sorted(word))].append(word)
return list(groups.values())
```

## bisect – бинарный поиск в отсортированном списке

```python
import bisect

arr = [1, 3, 3, 5, 7]

bisect.bisect_left(arr, 3)    # 1 – первая позиция, куда можно вставить 3
bisect.bisect_right(arr, 3)   # 3 – последняя такая позиция
bisect.insort(arr, 4)         # вставить с сохранением порядка
```

Полезные следствия:

```python
bisect_left(arr, x)                          # сколько элементов строго меньше x
bisect_right(arr, x) - bisect_left(arr, x)   # сколько элементов равны x

i = bisect_left(arr, x)                      # есть ли x в массиве
found = i < len(arr) and arr[i] == x
```

⚠️ Поиск – O(log N), но `insort` – **O(N)**, потому что вставка в список сдвигает хвост.
Если нужно много вставок в отсортированную структуру, Python из коробки хорошего решения
не даёт.

**Когда брать:** когда массив уже отсортирован и нужен быстрый поиск позиции. Классическое
применение – LIS за O(N log N).

## Прочие полезные инструменты

### functools.lru_cache – мемоизация в одну строку

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
```

Превращает экспоненциальную рекурсию в линейную. Требование: аргументы должны быть хешируемыми
(кортежи можно, списки нельзя). В Python 3.9+ есть короткий синоним `@cache`.

На собеседовании будь готов написать мемоизацию руками:

```python
def fib(n, memo=None):
    if memo is None:
        memo = {}
    if n in memo:
        return memo[n]
    if n < 2:
        return n
    memo[n] = fib(n - 1, memo) + fib(n - 2, memo)
    return memo[n]
```

### itertools

```python
from itertools import permutations, combinations, product, accumulate

list(permutations([1, 2, 3], 2))   # все упорядоченные пары
list(combinations([1, 2, 3], 2))   # [(1,2), (1,3), (2,3)]
list(product([0, 1], repeat=3))    # все битовые векторы длины 3
list(accumulate([1, 2, 3, 4]))     # [1, 3, 6, 10] – префиксные суммы!
```

`accumulate` – самый короткий способ получить префиксные суммы.

Осторожно: `permutations` и `combinations` на собеседовании обычно **не подходят** – если задача
про перебор, от тебя ждут, что ты напишешь backtracking сам.

## Разбор: какую структуру взять

Шесть типовых формулировок и правильный выбор.

**1. «Найти два числа с суммой target»**
→ `dict` вида `значение: индекс`. Нужно не просто знать, что число встречалось, а вернуть
его индекс.

**2. «Есть ли в массиве дубликаты»**
→ `set`. Значение не нужно, только факт наличия. Ответ вообще в одну строку:
`len(set(arr)) != len(arr)`.

**3. «Сгруппировать анаграммы»**
→ `defaultdict(list)`, ключ – `tuple(sorted(word))`. Список кортежем, потому что ключ должен
быть хешируемым.

**4. «Найти k самых частых элементов»**
→ `Counter` для подсчёта плюс `heapq` для отбора топ-K. Две структуры, каждая под свой этап.

**5. «Кратчайший путь в лабиринте»**
→ `deque` для очереди BFS плюс `set` для `visited` с кортежами координат.

**6. «Проверить правильность скобок»**
→ `list` как стек. Порядок критичен, нужен именно последний открытый элемент.

Общий принцип, который виден из этих примеров: **в задаче часто нужны две структуры сразу** –
одна отвечает на быстрый вопрос, другая хранит порядок или значения. Это норма, а не признак
того, что ты выбрал неправильно.

def remove_elements(head, target):
    dummy = ListNode(0, head)     # фиктивный узел перед головой
    cur = dummy
    while cur.next:

            cur.next = cur.next.next

## Чек-лист «мой код медленный, почему?»

Пробеги по списку – в 90 % случаев причина здесь:

1. `x in list` внутри цикла – замени на `set`
2. `list.pop(0)` или `insert(0, x)` – замени на `deque`
3. Срез `arr[i:]` внутри цикла – работай с индексами
4. `sorted()`, `min()`, `max()`, `sum()` внутри цикла – вынеси наружу или считай инкрементально
5. Конкатенация строк `s += x` в цикле – собирай в список и `"".join(...)`
6. N вызовов `heappush` вместо одного `heapify`
7. Пересчёт суммы подотрезка с нуля – префиксные суммы или скользящее окно
8. Рекурсия без мемоизации там, где подзадачи повторяются – `@lru_cache`

## Карточки

### Q: По какому принципу выбирают структуру данных?

Структура – это не способ хранить, а способ быстро отвечать на конкретный вопрос. Смотришь,
какой вопрос будешь задавать чаще всего, и берёшь ту, что отвечает на него за O(1): «дай
элемент номер i» – list, «было ли уже» – set, «что связано с ключом» – dict, «сколько раз
встретился» – Counter, «кто следующий в очереди» – deque.

### Q: Почему поиск в множестве O(1), а в списке O(N)?

Список хранит элементы подряд и при `x in arr` честно перебирает их по одному. Множество
считает от элемента хеш, по хешу вычисляет номер ячейки и смотрит только туда – один шаг
независимо от размера. Поэтому время поиска в списке растёт с размером, а в множестве
не растёт вообще: на 100 000 элементов разница примерно в 3700 раз.

### Q: Три вопроса, по которым выбирают между list, dict и set?

1) Важен ли порядок или доступ по номеру – да, значит list. 2) Нужно ли хранить что-то вместе
с элементом – да, значит dict. 3) Нужны ли дубликаты – да, значит list или Counter, нет –
set. Часто в задаче нужны две структуры сразу: set отвечает «было ли», list хранит порядок.

### Q: Чем платят за скорость хеш-таблиц?

Элементы обязаны быть хешируемыми, то есть неизменяемыми – список в множество не положить.
Памяти нужно примерно вчетверо больше, потому что таблица держит запас пустых ячеек. Множество
не хранит порядок и не даёт доступа по индексу. Плюс формально O(1) только в среднем: при
массовых коллизиях поиск вырождается в O(N), хотя на практике это не встречается.

### Q: Какие операции списка стоят O(N) и чем их заменить?

`x in arr` и `arr.index(x)` – линейный поиск, замена на `set` или `dict`. `arr.pop(0)`
и `insert(0, x)` – сдвиг всего списка, замена на `collections.deque`. `arr.remove(x)` – поиск
плюс сдвиг. Срез `arr[a:b]` копирует. `min`, `max`, `sum` внутри цикла превращают O(N) в O(N²).

### Q: Зачем нужен deque, если есть list?

У списка `pop(0)` стоит O(N): все элементы сдвигаются влево, и цикл становится квадратичным.
У `deque` добавление и удаление с обоих концов O(1). На очереди из 100 000 элементов разница
932 мс против 5 мс. Главное применение – очередь BFS. Для стека `deque` не нужен: у списка
`append` и `pop` и так O(1).

### Q: Когда нужна куча, а когда достаточно sorted или min?

`min(arr)` подходит, если минимум нужен один раз – это O(N). Куча нужна, когда набор постоянно
меняется и минимум нужен многократно (O(log N) на операцию вместо пересортировки), или когда
данные приходят потоком и надо всё время держать топ-K. Если нужно отсортировать всё один раз,
`sorted()` проще и быстрее.

### Q: Для K наибольших нужна min-heap или max-heap?

Min-heap размера K. Логика не в том, что мы ищем, а в том, кого надо быстро вытеснить: куча
должна мгновенно отдавать худшего из тех, кого мы держим, чтобы заменить его новым кандидатом.
Симметрично для K наименьших нужна max-heap (в Python – через хранение отрицательных значений).

### Q: Что делает `heapify` и почему это важно?

Превращает готовый список в кучу на месте за O(N), тогда как N вызовов `heappush` стоят
O(N log N). Правило: если все данные уже есть – `heapify`, если элементы приходят по одному –
`heappush`. Это один из пунктов чек-листа «почему мой код медленный».

### Q: Чем полезны Counter и defaultdict?

`Counter` считает частоты, не падает на отсутствующем ключе, умеет `most_common(k)` и арифметику
множеств: `Counter(a) == Counter(b)` – проверка на анаграммы за O(N). `defaultdict` создаёт
значение по умолчанию автоматически, что убирает `if key not in d: d[key] = []` из построения
графа и любой группировки.

### Q: В чём суперсила кортежа помимо неизменяемости?

Он хешируем, поэтому годится в ключи словаря, элементы множества и аргументы `@lru_cache` –
отсюда `visited.add((r, c))` и `groups[tuple(sorted(word))]`. Второе: кортежи сравниваются
лексикографически, что даёт бесплатную многокритериальную сортировку – `sort(key=lambda w:
(len(w), w))` и кучу пар `(priority, value)`.

### Q: Что делает bisect и где подвох?

`bisect_left` и `bisect_right` находят позицию для вставки в отсортированный список за
O(log N); их разность даёт количество элементов, равных x. Подвох в `insort`: сам поиск
логарифмический, но вставка в список сдвигает хвост, поэтому операция целиком O(N). Классическое
применение bisect – LIS за O(N log N).
