- писать каркас окна переменного размера не задумываясь;
- объяснять, почему вложенный `while` не делает алгоритм квадратичным.

Паттерн 3 из 7. Шпаргалка по опознанию и порядок прохождения – в конспекте «Как опознать
паттерн».

## Признаки

Триггерные слова в условии: **«подмассив»**, **«подстрока»**, **«непрерывный»**, плюс:

- «самый длинный / самый короткий подотрезок, такой что …»
- «подотрезок фиксированной длины k»
- «максимальная сумма подмассива длины k»
- «подстрока без повторяющихся символов»

Ключевое отличие от подпоследовательности: **элементы идут подряд**. Если в задаче
«подпоследовательность» (можно выкидывать элементы) – окно не подходит, это скорее динамическое
программирование.

## Идея

Наивно: перебрать все начала и все концы – O(n²), пересчитывая сумму или множество внутри.
Но при сдвиге окна на один элемент состояние меняется чуть-чуть: один элемент вошёл, один вышел.
Значит можно поддерживать состояние инкрементально – O(n) на весь проход.

## Шаблон А: окно фиксированного размера k

```python
def max_sum_window(arr, k):
    window_sum = sum(arr[:k])
    best = window_sum
    for right in range(k, len(arr)):
        window_sum += arr[right] - arr[right - k]   # вошёл новый, вышел старый
        best = max(best, window_sum)
    return best
```

## Шаблон Б: окно переменного размера (самый важный!)

Это универсальный каркас. Выучи его структуру – она одинакова для десятков задач.

```python
def longest_valid_window(arr):
    left = 0
    state = {}          # что-то, описывающее текущее окно
    best = 0

    for right in range(len(arr)):
        # 1. расширяем окно вправо: добавляем arr[right] в состояние
        add(arr[right], state)

        # 2. пока окно НЕвалидно - сжимаем слева
        while not is_valid(state):
            remove(arr[left], state)
            left += 1

        # 3. здесь окно [left, right] валидно - обновляем ответ
        best = max(best, right - left + 1)

    return best
```

Писать конкретную задачу означает заполнить три дырки: **что такое состояние**, **когда окно
невалидно**, **как убрать элемент из состояния**. Больше в каркасе ничего не меняется.

Для задачи «самое **короткое** валидное окно» структура зеркальная: while-цикл сжимает,
**пока окно валидно**, и ответ обновляется внутри while.

```python
def shortest_valid_window(arr):
    left = 0
    best = float('inf')
    for right in range(len(arr)):
        add(arr[right], state)
        while is_valid(state):
            best = min(best, right - left + 1)   # ответ обновляем ВНУТРИ
            remove(arr[left], state)
            left += 1
    return best if best != float('inf') else 0
```

**Почему это O(n), хотя есть вложенный while:** `left` только увеличивается и никогда
не уменьшается. За весь алгоритм он пройдёт максимум n шагов. Итого 2n операций – O(n).
Это ровно то объяснение, которое ждёт интервьюер, когда спросит «а почему не O(n²)?».

## Разбор: Longest Substring Without Repeating Characters (LC 3)

> Найти длину самой длинной подстроки без повторяющихся символов.

**Что такое состояние?** Множество символов в текущем окне.
**Когда окно невалидно?** Когда новый символ уже есть в множестве.
**Как сжимать?** Убирать символы слева, пока дубликат не уйдёт.

```python
def length_of_longest_substring(s):
    seen = set()
    left = 0
    best = 0

    for right in range(len(s)):
        while s[right] in seen:          # окно невалидно
            seen.remove(s[left])
            left += 1
        seen.add(s[right])
        best = max(best, right - left + 1)

    return best
```

Время O(n), память O(min(n, размер алфавита)).

**Вариант с оптимизацией** – вместо посимвольного сжатия прыгнуть сразу:

```python
def length_of_longest_substring(s):
    last_pos = {}       # символ -> последний индекс
    left = 0
    best = 0
    for right, ch in enumerate(s):
        if ch in last_pos and last_pos[ch] >= left:
            left = last_pos[ch] + 1       # прыгаем за прошлое вхождение
        last_pos[ch] = right
        best = max(best, right - left + 1)
    return best
```

Проверка `last_pos[ch] >= left` обязательна: символ мог встречаться раньше, но уже выпасть
из окна, и без неё `left` уехал бы назад.

## Карточки

### Q: По каким словам опознаётся скользящее окно?

«Подмассив», «подстрока», «непрерывный», а также «самый длинный или самый короткий подотрезок,
такой что…» и «подотрезок фиксированной длины k». Ключевое условие – элементы идут подряд.
Слово «подпоследовательность» означает, что элементы можно выкидывать, и окно не подходит.

### Q: В чём идея окна по сравнению с наивным перебором?

Наивно перебираются все начала и концы, и внутри заново считается сумма или множество – O(n²).
Но при сдвиге окна на один элемент состояние меняется чуть-чуть: один элемент вошёл, один вышел.
Поддерживая состояние инкрементально, весь проход укладывается в O(n).

### Q: Назови каркас окна переменного размера.

Три шага в цикле по правой границе: расширить окно (добавить `arr[right]` в состояние); пока
окно невалидно – сжимать слева, убирая `arr[left]` и увеличивая `left`; после сжатия окно
валидно, обновить ответ как `right - left + 1`. Задача заполняет три дырки: что такое состояние,
когда окно невалидно, как убрать элемент.

### Q: Чем отличается поиск самого короткого валидного окна?

Структура зеркальная: `while` сжимает окно, **пока оно валидно**, а ответ обновляется **внутри**
этого while, до сдвига `left`. В варианте на максимум ответ обновляется после while, когда окно
уже стало валидным. Ответ инициализируется `float('inf')` и в конце проверяется на «не нашли».

### Q: Почему окно работает за O(n), хотя внутри цикла есть while?

Потому что `left` только увеличивается и никогда не уменьшается: за весь алгоритм он сделает
не больше n шагов, как и `right`. Итого около 2n операций, то есть O(n). Это именно тот ответ,
которого ждёт интервьюер на вопрос «а почему не O(n²)?».

### Q: Как решается «самая длинная подстрока без повторов»?

Состояние – множество символов окна; окно невалидно, когда новый символ уже в множестве; сжимаем
слева, пока дубликат не уйдёт. O(n) времени, O(min(n, размер алфавита)) памяти. Оптимизация:
хранить `символ -> последний индекс` и прыгать `left` сразу за прошлое вхождение.

### Q: Какая ловушка в варианте окна с прыжком по last_pos?

Нужна проверка `last_pos[ch] >= left`: символ мог встретиться раньше, но уже выпасть из текущего
окна. Без неё `left` уедет назад, окно «расширится» задним числом и ответ станет больше
настоящего.

### Q: Как считается сумма в окне фиксированного размера k?

Один раз берётся сумма первых k элементов, дальше на каждом шаге `window_sum += arr[right] -
arr[right - k]`: вошёл новый элемент, вышел старый. Пересчёт за O(1) вместо O(k), весь проход –
O(n).
