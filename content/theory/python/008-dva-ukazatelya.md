## Что ты будешь уметь после этого урока

- решать задачи на отсортированном массиве за O(N) вместо O(N²);
- объяснять, почему сдвиг указателя не теряет ответ;
- переупорядочивать массив на месте за O(1) памяти.

Паттерн 2 из 7. Шпаргалка по опознанию и порядок прохождения – в конспекте «Как опознать
паттерн».

## Признаки

- Массив **отсортирован** (или его можно отсортировать)
- Ищем пару или тройку с заданной суммой
- Нужно сравнить начало и конец: палиндром, разворот
- Нужно убрать дубликаты или переставить элементы **на месте**, за O(1) памяти
- В условии просят O(1) дополнительной памяти

## Две разновидности

### Указатели с концов (навстречу друг другу)

```python
lo, hi = 0, len(arr) - 1
while lo < hi:
    s = arr[lo] + arr[hi]
    if s == target:
        return [lo, hi]
    elif s < target:
        lo += 1        # нужна сумма побольше -> двигаем левый вправо
    else:
        hi -= 1        # нужна сумма поменьше -> двигаем правый влево
```

**Почему это корректно** (это важно уметь объяснить на собесе): если `arr[lo] + arr[hi] < target`,
то `arr[lo]` в паре с **любым** элементом левее `hi` даст ещё меньшую сумму. Значит `arr[lo]`
вообще не может участвовать в ответе, и его можно безопасно выбросить. Каждый шаг отбрасывает
целую строку или столбец воображаемой таблицы всех пар – отсюда O(n) вместо O(n²).

Это и есть общая форма обоснования для всего паттерна: **сдвиг указателя разрешён ровно тогда,
когда доказано, что отброшенный элемент не может быть частью ответа.** Если такого довода нет,
два указателя не применимы, сколько бы массив ни был отсортирован.

### Быстрый и медленный указатель (оба слева)

Используется, чтобы переупорядочить массив на месте.

```python
# Убрать все вхождения val, вернуть новую длину
slow = 0
for fast in range(len(arr)):
    if arr[fast] != val:
        arr[slow] = arr[fast]
        slow += 1
return slow
```

Мысленная модель: `slow` – граница «уже обработанной, правильной части», `fast` – сканирующий
указатель. Всё, что левее `slow`, – готовый ответ; всё, что между `slow` и `fast`, – мусор,
который будет перезаписан.

## Разбор: 3Sum (LC 15)

> Найти все уникальные тройки, дающие в сумме 0.

Классический medium, который спрашивают постоянно.

**Ход мысли:** тройки перебрать нельзя – O(n³). Но если зафиксировать первый элемент, задача
сводится к «найти пару с суммой `-nums[i]`» – а это два указателя за O(n), если массив
отсортирован. Итого O(n) фиксаций × O(n) поиска = O(n²), плюс сортировка O(n log n).

Отдельная сложность – не выдать дубликаты. Решается пропуском одинаковых значений.

```python
def three_sum(nums):
    nums.sort()
    result = []
    n = len(nums)

    for i in range(n - 2):
        # пропускаем дубликаты первого элемента
        if i > 0 and nums[i] == nums[i - 1]:
            continue
        # массив отсортирован: если сам минимум > 0, дальше только больше
        if nums[i] > 0:
            break

        lo, hi = i + 1, n - 1
        while lo < hi:
            s = nums[i] + nums[lo] + nums[hi]
            if s < 0:
                lo += 1
            elif s > 0:
                hi -= 1
            else:
                result.append([nums[i], nums[lo], nums[hi]])
                lo += 1
                hi -= 1
                # пропускаем дубликаты второго элемента
                while lo < hi and nums[lo] == nums[lo - 1]:
                    lo += 1
    return result
```

Время O(n²), память O(1) не считая ответа.

Приём «свести задачу на k элементов к задаче на k−1» работает и дальше: 4Sum – это два вложенных
цикла фиксации плюс те же два указателя внутри, O(n³).

## Карточки

### Q: По каким признакам в условии видно паттерн «два указателя»?

Массив отсортирован или его можно отсортировать; ищем пару или тройку с заданной суммой; надо
сравнить начало и конец (палиндром, разворот); надо переставить элементы или убрать дубликаты
на месте. Отдельный сильный сигнал – требование O(1) дополнительной памяти.

### Q: Почему сдвиг указателя в паре с концов не теряет ответ?

Если `arr[lo] + arr[hi] < target`, то `arr[lo]` с любым элементом левее `hi` даст ещё меньшую
сумму, значит `arr[lo]` не может входить в ответ и его можно выбросить. Каждый шаг отбрасывает
целую строку таблицы пар, поэтому O(n) вместо O(n²). Без такого довода паттерн неприменим.

### Q: Что за роли у быстрого и медленного указателей?

`slow` – граница уже обработанной, правильной части массива; `fast` сканирует вход. Всё левее
`slow` – готовый ответ, всё между `slow` и `fast` – мусор, который будет перезаписан. Так за один
проход и O(1) памяти удаляются вхождения значения, дубликаты, нули сдвигаются в конец.

### Q: Как 3Sum сводится к двум указателям и какая у неё сложность?

Массив сортируется, первый элемент фиксируется циклом, и для остатка решается «найти пару
с суммой `-nums[i]`» парой указателей с концов. Итого O(n) фиксаций на O(n) поиска = O(n²),
плюс O(n log n) на сортировку. Память O(1), если не считать ответ.

### Q: Как в 3Sum не выдать дубликаты троек?

Пропуском одинаковых значений на отсортированном массиве: внешний цикл пропускает `nums[i]`,
равный предыдущему, а после найденной тройки внутренний `while` сдвигает `lo`, пока
`nums[lo] == nums[lo - 1]`. Дополнительно `break` при `nums[i] > 0` отсекает заведомо
положительные суммы.

### Q: Когда брать два указателя, а когда хеш-таблицу?

Хеш работает на неотсортированном входе и даёт O(n), но стоит O(n) памяти. Два указателя требуют
порядка (иногда ценой сортировки O(n log n)), зато память O(1) и естественно обрабатываются
дубликаты. Явное «на месте» или «O(1) памяти» в условии решает выбор.
