## Признаки

- В условии фигурируют интервалы `[start, end]`: встречи, отрезки, расписания
- «Слить пересекающиеся», «сколько нужно комнат», «максимум непересекающихся»
- Задача выглядит хаотично, но становится простой, если элементы упорядочить

## Главный приём

**Отсортировать по началу интервала.** После этого задача почти всегда решается одним линейным
проходом: отсортированный вход даёт право смотреть только на последний обработанный интервал,
а не на все предыдущие.

## Шаблон: слияние интервалов

```python
def merge(intervals):
    intervals.sort(key=lambda x: x[0])     # по началу
    merged = []
    for start, end in intervals:
        if merged and start <= merged[-1][1]:
            # пересекается с последним - расширяем его
            merged[-1][1] = max(merged[-1][1], end)
        else:
            merged.append([start, end])
    return merged
```

Время O(n log n) – доминирует сортировка.

Две тонкости, на которых чаще всего спотыкаются: сравнивать надо с **последним добавленным**
интервалом, а не с текущим входным, и брать `max(merged[-1][1], end)`, потому что новый интервал
может целиком лежать внутри предыдущего.

## Шаблон: сколько интервалов пересекается одновременно (комнаты для встреч)

Приём называется **«разделение точек»** (sweep line): вместо интервалов рассматриваем отдельно
все начала и все концы. Интервал перестаёт быть единым объектом, остаются только события
«кто-то пришёл» и «кто-то ушёл» на общей временной оси.

```python
def min_meeting_rooms(intervals):
    starts = sorted(i[0] for i in intervals)
    ends = sorted(i[1] for i in intervals)

    rooms = 0
    best = 0
    s = e = 0
    while s < len(starts):
        if starts[s] < ends[e]:
            rooms += 1          # началась встреча - заняли комнату
            s += 1
            best = max(best, rooms)
        else:
            rooms -= 1          # закончилась - освободили
            e += 1
    return best
```

Альтернативный способ той же задачи – через минимальную кучу концов: в куче лежат времена
окончания занятых комнат, и на каждой новой встрече освобождается та, что закончилась раньше
всех. Про `heapq` – в конспекте «Выбор структуры данных».

## Разбор: Non-overlapping Intervals (LC 435)

> Минимум интервалов, которые нужно удалить, чтобы остальные не пересекались.

**Ход мысли:** «удалить минимум» = «оставить максимум». Это классическая жадная задача
о планировании. Ключевая идея: сортировать по **концу**, а не по началу – жадно берём интервал,
который заканчивается раньше всех, потому что он оставляет больше всего места для остальных.

```python
def erase_overlap_intervals(intervals):
    intervals.sort(key=lambda x: x[1])     # по КОНЦУ
    kept = 0
    last_end = float('-inf')
    for start, end in intervals:
        if start >= last_end:
            kept += 1
            last_end = end
    return len(intervals) - kept
```

Обрати внимание: сортировка по началу здесь даёт неправильный ответ. Выбор ключа сортировки –
и есть суть задачи.

| Что нужно | Ключ сортировки |
|---|---|
| слить пересекающиеся, вставить интервал | по началу |
| оставить максимум непересекающихся, минимум удалений | по концу |
| посчитать максимум одновременных | начала и концы отдельно (sweep line) |

## Карточки

### Q: Какой главный приём в задачах на интервалы?

Отсортировать по началу интервала. После сортировки задача почти всегда решается одним линейным
проходом, потому что достаточно смотреть на последний обработанный интервал, а не на все
предыдущие. Сложность O(n log n), доминирует сортировка.

### Q: Как слить пересекающиеся интервалы?

Отсортировать по началу и идти по списку: если начало текущего не больше конца последнего
добавленного, расширить последний до `max(последний конец, текущий конец)`, иначе добавить
текущий как новый. `max` обязателен: новый интервал может целиком лежать внутри предыдущего.

### Q: Почему в Non-overlapping Intervals сортируют по концу, а не по началу?

Потому что «удалить минимум» равно «оставить максимум», а это жадная задача о планировании:
интервал, который заканчивается раньше всех, оставляет больше всего места для остальных.
Сортировка по началу здесь даёт неправильный ответ – выбор ключа и есть суть задачи.

### Q: Что такое разделение точек (sweep line)?

Приём, при котором интервал перестаёт быть единым объектом: отдельно сортируются все начала
и все концы, и по общей оси идут события «пришёл» и «ушёл». Счётчик занятых комнат растёт
на начале и падает на конце, максимум счётчика – ответ на «сколько нужно комнат».

### Q: Как выбрать ключ сортировки в задаче на интервалы?

Слить пересекающиеся или вставить интервал – по началу. Оставить максимум непересекающихся
или удалить минимум – по концу. Посчитать максимум одновременных – начала и концы сортируются
отдельно, это sweep line.

### Q: Какой ещё способ решить «сколько нужно переговорок» кроме sweep line?

Минимальная куча концов: интервалы перебираются по началу, в куче лежат времена окончания
занятых комнат. Если самая ранняя из них уже освободилась – переиспользуем её, иначе заводим
новую. Размер кучи в максимуме и есть ответ.
