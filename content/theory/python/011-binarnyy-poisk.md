## Что ты будешь уметь после этого урока

- писать шаблон поиска границы без сомнений, где ставить `+1`;
- узнавать «бинпоиск по ответу» там, где никакого отсортированного массива нет;
- формулировать инвариант вслух – это то, что спрашивает интервьюер.

Паттерн 5 из 7. Шпаргалка по опознанию и порядок прохождения – в конспекте «Как опознать
паттерн».

## Признаки

Явные:

- Массив отсортирован, надо что-то найти – значит ждут O(log n)

Неочевидные (и куда более частые на medium):

- «Найти **минимальное или максимальное** значение, при котором выполняется условие»
- Есть функция `check(x)`, которая для маленьких x возвращает False, а начиная с какого-то –
  True (**монотонность**)
- В условии есть слова «минимальная скорость», «минимальная вместимость», «за сколько дней» –
  это почти всегда бинпоиск по ответу

## Шаблон А: классический поиск значения

```python
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:                    # <= потому что границы включительные
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

## Шаблон Б: поиск границы (важнее классического!)

Найти **первый** индекс, где условие становится истинным. Это тот шаблон, который решает
большинство medium-задач на бинпоиск.

```python
def find_first_true(arr):
    lo, hi = 0, len(arr)               # hi = len(arr), полуинтервал [lo, hi)
    while lo < hi:                     # строгое <
        mid = (lo + hi) // 2
        if condition(arr[mid]):
            hi = mid                   # mid может быть ответом - не отбрасываем
        else:
            lo = mid + 1               # mid точно не ответ
    return lo                          # lo == hi - первая позиция с True
```

Инвариант, который стоит проговорить вслух: **всё, что левее `lo`, – False; всё, что правее
или равно `hi`, – True.** Цикл сужает интервал, пока границы не сойдутся.

Отсюда же берутся ответы на два вечных вопроса. `<` вместо `<=`, потому что интервал
полуоткрытый: `hi` – это не элемент, а граница «первого True». `+1` ставится только там, где
`mid` **точно** не может быть ответом; в ветке, где `mid` ещё кандидат, границу двигают ровно
на `mid`.

**Совет:** не пытайся каждый раз выводить, где `+1`, а где нет. Выучи один шаблон (Б) наизусть,
буквально до автоматизма пальцев, и своди задачи к нему. Это экономит кучу нервов.

## Шаблон В: бинарный поиск по ответу

Самый «взрослый» вариант. Ищем не в массиве, а **в диапазоне возможных ответов**.

```python
def min_valid_answer(lo, hi, check):
    # check(x) монотонна: False, False, ..., False, True, True, ...
    while lo < hi:
        mid = (lo + hi) // 2
        if check(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo
```

Это тот же шаблон Б, только вместо `arr[mid]` стоит вычисление `check(mid)`, а границы – не
индексы, а минимально и максимально возможный ответ.

## Разбор: Koko Eating Bananas (LC 875)

> Есть кучи бананов. Коко ест со скоростью k бананов в час, за час доедает максимум одну кучу.
> Найти минимальную k, при которой она успеет за h часов.

**Ход мысли:** перебирать все k от 1 до max(piles) – O(max·n), слишком долго. Но заметим
монотонность: если Коко успевает со скоростью k, то со скоростью k+1 тем более успеет. Значит
функция «успевает ли?» имеет вид False…False, True…True – бинпоиск по k.

```python
import math

def min_eating_speed(piles, h):
    def hours_needed(k):
        return sum(math.ceil(p / k) for p in piles)

    lo, hi = 1, max(piles)
    while lo < hi:
        mid = (lo + hi) // 2
        if hours_needed(mid) <= h:
            hi = mid            # успевает - пробуем медленнее
        else:
            lo = mid + 1        # не успевает - надо быстрее
    return lo
```

Время O(n · log(max(piles))).

Границы выбраны не наугад: при k = 1 ответ заведомо худший, но допустимый, а быстрее
max(piles) есть бессмысленно – за час всё равно съедается максимум одна куча.

**Как опознать бинпоиск по ответу:** спроси себя – «если я угадаю ответ, смогу ли я быстро
проверить, подходит ли он? и монотонна ли эта проверка?». Если да на оба вопроса – это бинпоиск
по ответу.

## Карточки

### Q: Как выглядит шаблон поиска границы и что он возвращает?

Полуинтервал `lo, hi = 0, len(arr)`, цикл `while lo < hi`, `mid = (lo + hi) // 2`. Если условие
на `mid` истинно – `hi = mid` (mid ещё может быть ответом), иначе `lo = mid + 1` (mid точно
не ответ). Возвращается `lo`: позиция первого элемента, где условие становится истинным.

### Q: Сформулируй инвариант бинарного поиска границы.

Всё, что левее `lo`, – False; всё, что правее или равно `hi`, – True. Цикл сужает интервал,
сохраняя это свойство, и завершается, когда границы сходятся, – значит `lo` и есть первая
позиция с True. Это именно та формулировка, которую ждут на собеседовании.

### Q: Почему в одном шаблоне `while lo <= hi`, а в другом `while lo < hi`?

В классическом поиске значения границы включительные, `hi = len(arr) - 1`, и интервал
из одного элемента ещё надо проверить – отсюда `<=`. В поиске границы интервал полуоткрытый,
`hi = len(arr)` не элемент, а граница; когда `lo == hi`, проверять уже нечего, ответ найден.

### Q: Где в бинпоиске ставится `+1`, а где нет?

`+1` ставится только там, где `mid` **точно** не может быть ответом: тогда его можно отбросить.
В ветке, где `mid` ещё кандидат, граница двигается ровно на `mid`, без сдвига. Вывод каждый раз
заново – источник ошибок, поэтому шаблон границы учат наизусть и сводят задачи к нему.

### Q: Как опознать бинарный поиск по ответу?

Двумя вопросами к себе: если я угадаю ответ, смогу ли быстро проверить, подходит ли он, и
монотонна ли эта проверка (False…False, True…True). Два «да» – ищем не в массиве, а в диапазоне
возможных ответов. Словесные маркеры: «минимальная скорость», «минимальная вместимость»,
«за сколько дней».

### Q: Разбери Koko Eating Bananas: что за проверка и почему она монотонна.

`check(k)` – успевает ли Коко съесть все кучи за h часов при скорости k, то есть
`sum(ceil(p / k) for p in piles) <= h`. Монотонность очевидна: если успевает при k, то при k+1
тем более. Диапазон поиска – от 1 до max(piles); больше max(piles) бессмысленно, за час всё
равно съедается максимум одна куча. Итог O(n · log(max(piles))).
