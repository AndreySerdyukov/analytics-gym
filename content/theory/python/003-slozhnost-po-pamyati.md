## Что ты будешь уметь после этого урока

- считать, сколько дополнительной памяти ест твой код;
- видеть скрытый расход на стек рекурсии, срезы и копии;
- знать приёмы, которые снижают память, и когда их применять;
- отвечать на вопрос «а можешь то же самое за O(1) памяти?».

Парный урок – «Временная сложность». Все базовые правила подсчёта (константы отбрасываем,
старшее слагаемое оставляем, вложенное перемножается) работают здесь точно так же. Отличается
только то, **что именно** мы считаем.

## Почему это спрашивают

Три причины, по которым память – не второстепенный вопрос:

1. **Это реальное ограничение.** На LeetCode есть лимит памяти, в проде тем более. Решение
   за O(N²) памяти на входе в миллион элементов просто не запустится.
2. **Это индикатор понимания.** Кандидат, который сам называет память, показывает, что видит
   всю картину, а не только время.
3. **Это отдельный источник задач.** Формулировка «сделай то же самое, не создавая
   дополнительный массив» – стандартный способ усложнить задачу на собеседовании.

## Дополнительная память против полной

Это первое, что надо чётко разделять.

| Термин | Что входит |
|---|---|
| **Полная память** (total space) | вход + всё, что создал алгоритм |
| **Дополнительная память** (auxiliary space) | только то, что создал алгоритм |

**Когда говорят «сложность по памяти», почти всегда имеют в виду дополнительную.** Входные
данные уже существуют, мы за них не отвечаем.

```python
def total(arr):
    s = 0                    # одна переменная
    for x in arr:
        s += x
    return s
# дополнительная память: O(1)
# полная: O(N), потому что сам массив занимает N
```

Правильная формулировка на собеседовании: **«O(1) дополнительной памяти»**. Слово
«дополнительной» снимает всю двусмысленность.

## Считать ли память под ответ

Отдельный тонкий момент. Если задача просит вернуть список из N элементов, то O(N) памяти
под результат неизбежны – значит, их обычно **не считают**.

```python
def doubled(arr):
    return [x * 2 for x in arr]
# память под результат O(N), но она обязательна по условию
# говорим: "O(1) дополнительной памяти, не считая выходного массива"
```

Это ровно та фраза, которую стоит произнести: *«O(1) дополнительно, если не считать память
под ответ»*. Так делают все нормальные разборы.

Исключение – когда размер ответа сам по себе является предметом обсуждения. Например,
в backtracking-задачах ответ может быть экспоненциальным, и об этом надо сказать явно.

## Иерархия по памяти

Классов меньше, чем у времени, и встречаются они неравномерно: почти всё на практике –
это O(1), O(log N) или O(N).

| Класс | Что это значит | Типичный пример |
|---|---|---|
| `O(1)` | фиксированное число переменных | два указателя, счётчики, обмен на месте |
| `O(log N)` | стек рекурсии глубины log N | бинпоиск рекурсивно, быстрая сортировка в среднем, обход сбалансированного дерева |
| `O(N)` | структура размером с вход | словарь, множество, очередь BFS, массив ДП, стек рекурсии на N уровней |
| `O(N + M)` | две независимые структуры | граф: список смежности O(V + E) |
| `O(N·M)` | двумерная таблица | ДП на двух строках, матрица расстояний |
| `O(2ᴺ)` | все подмножества хранятся сразу | перебор с сохранением всех вариантов |

Ориентир по абсолютным числам: **массив из 10⁶ чисел в Python съедает порядка 40 МБ**.
Из 10⁷ – уже около 400 МБ, и это близко к лимиту большинства проверяющих систем. Считай,
что 10⁷ элементов в списке – граница, за которую лучше не заходить.

## Три источника расхода памяти

Когда считаешь память своего кода, проверь эти три канала. Первый очевиден, два других – нет.

### Источник 1. Явно созданные структуры

Самое простое: всё, что ты создал руками.

```python
seen = set()                          # O(N)
result = []                           # O(N)
counts = defaultdict(int)             # O(N)
dp = [[0] * m for _ in range(n)]      # O(N·M)
```

### Источник 2. Стек вызовов рекурсии

Главный скрытый расход. Ему посвящён следующий раздел.

```python
def depth(node):
    if not node:
        return 0
    return 1 + max(depth(node.left), depth(node.right))
# создали ноль структур, но память O(H) на стек вызовов
```

### Источник 3. Скрытые копии

Операции, которые незаметно выделяют память:

```python
sub = arr[i:j]            # срез ВСЕГДА копирует: O(j−i)
new = sorted(arr)         # новый список: O(N)
s = "".join(parts)        # новая строка: O(суммарной длины)
rev = arr[::-1]           # копия: O(N)
keys = list(d.keys())     # копия ключей: O(N)
t = tuple(lst)            # копия: O(N)
```

Особенно коварны срезы внутри цикла: они дают и лишнее время, и лишнюю память.

**Отдельный факт про сортировку.** `list.sort()` называют сортировкой «на месте», и по
результату это так – новый список не создаётся. Но Timsort внутри использует временный буфер,
поэтому строго говоря `sort()` требует до O(N) дополнительной памяти. На собеседовании обычно
достаточно сказать «сортировка на месте, O(1) дополнительно с точки зрения структуры данных»;
но если тебя спросят про Python конкретно – корректный ответ «Timsort требует до O(N)
вспомогательной памяти».

## Стек вызовов: главная скрытая память

### Почему рекурсия стоит памяти

Каждый незавершённый вызов функции хранится в стеке: его локальные переменные, аргументы,
точка возврата. Пока рекурсия не начала «схлопываться», все эти кадры лежат в памяти
одновременно.

**Память рекурсии = максимальная глубина рекурсии.**

```python
def countdown(n):
    if n == 0:
        return
    countdown(n - 1)
# ни одной структуры не создано
# память: O(N) – на стек из N кадров
```

Это ровно тот случай, когда код выглядит как O(1), а на деле O(N). Классическая ошибка
на собеседовании.

### Деревья: O(H), а не O(N)

Для рекурсивного обхода дерева глубина стека равна **высоте дерева H**, а не числу узлов.

```python
def max_depth(node):
    if not node:
        return 0
    return 1 + max(max_depth(node.left), max_depth(node.right))
```

| Форма дерева | Высота | Память |
|---|---|---|
| Сбалансированное | H ≈ log N | **O(log N)** |
| Вырожденное («палка») | H = N | **O(N)** |

Правильный ответ на собеседовании: **«O(H) памяти на стек, где H – высота дерева; для
сбалансированного это O(log N), в худшем случае O(N)»**. Такой ответ показывает, что ты
понимаешь разницу, а не заучил цифру.

### Другие типичные глубины

| Алгоритм | Память на стек |
|---|---|
| Бинарный поиск рекурсивно | O(log N) |
| Сортировка слиянием | O(log N) на стек + O(N) на слияние = O(N) |
| Быстрая сортировка | O(log N) в среднем, O(N) в худшем |
| DFS по графу | O(V) – в худшем случае весь граф это одна цепочка |
| Backtracking | O(глубины дерева решений), обычно O(N) |

### Предел рекурсии в Python

По умолчанию Python допускает около 1000 уровней вложенности. Обход дерева из 10⁴ узлов,
вытянутого в линию, упадёт с `RecursionError`.

```python
import sys
sys.setrecursionlimit(10 ** 6)
```

На LeetCode это иногда требуется. На собеседовании достаточно упомянуть, что ты об этом знаешь.

### Как убрать рекурсию

Любую рекурсию можно переписать итеративно, заменив стек вызовов явным стеком. Память при этом
формально та же O(H), но исчезает риск `RecursionError` и снижаются накладные расходы.

```python
# Рекурсивный обход в глубину
def preorder(node, out):
    if not node:
        return
    out.append(node.val)
    preorder(node.left, out)
    preorder(node.right, out)

# Тот же обход итеративно
def preorder_iter(root):
    out, stack = [], [root] if root else []
    while stack:
        node = stack.pop()
        out.append(node.val)
        if node.right:
            stack.append(node.right)     # правого кладём первым
        if node.left:
            stack.append(node.left)      # левый обработается раньше
    return out
```

Упомянуть возможность итеративной версии – хороший ход на собеседовании, даже если ты пишешь
рекурсивную.

## Сколько реально весят структуры Python

Числа получены на CPython 3.11 через `sys.getsizeof`. Точные значения зависят от версии,
но порядок стабилен.

| Что | Размер | Комментарий |
|---|---|---|
| Небольшое `int` | 28 байт | да, двадцать восемь – это не 4 и не 8 |
| `int` порядка 2³⁰ | 32 байта | питоновские числа неограниченной длины |
| Пустой список | 56 байт | накладные расходы объекта |
| Список из N чисел | 8·N байт указателей **плюс** сами объекты | итого ≈ 36 байт на элемент |
| `set` из N чисел | ≈ 33 байта на элемент | плюс объекты |
| `dict` из N пар | ≈ 37 байт на элемент | плюс объекты |
| `array.array('l')` из N | ≈ 8 байт на элемент | компактно, но только числа одного типа |

**Практические выводы:**

1. **Список из 10⁶ чисел – это около 40 МБ, а не 8 МБ.** Питон хранит указатели на объекты,
   а не сами значения.
2. **Множество и словарь примерно вчетверо «дороже» на элемент, чем кажется.** Разменивая
   память на время через `set`, ты платишь ощутимо.
3. Для больших однородных числовых массивов существуют `array.array` и `numpy` – в 4–5 раз
   компактнее. В алгоритмических задачах это почти никогда не нужно, но знать полезно.
4. Маленькие целые числа от −5 до 256 Python кеширует и переиспользует, так что список
   из миллиона нулей дешевле, чем из миллиона разных чисел.

На собеседовании такие детали не спрашивают – там считают в O-нотации. Но понимать порядок
величин полезно, чтобы не удивляться, почему решение упёрлось в лимит.

## Как считать: разборы

### O(1)

```python
def max_subarray(nums):
    best = cur = nums[0]
    for x in nums[1:]:          # ⚠️ вот здесь есть нюанс
        cur = max(x, cur + x)
        best = max(best, cur)
    return best
```

Переменных фиксированное число, но `nums[1:]` – это **срез, то есть копия массива**, а значит
O(N) памяти. Чтобы получить честный O(1):

```python
def max_subarray(nums):
    best = cur = nums[0]
    for i in range(1, len(nums)):     # индексы вместо среза
        cur = max(nums[i], cur + nums[i])
        best = max(best, cur)
    return best
# O(1) дополнительной памяти
```

Это тот самый случай, когда красивая питоновская запись стоит памяти. На собеседовании стоит
проговорить: *«я заменил срез на индексы, чтобы не копировать массив»*.

### O(N)

```python
def two_sum(nums, target):
    seen = {}                          # растёт до N элементов
    for i, x in enumerate(nums):
        if target - x in seen:
            return [seen[target - x], i]
        seen[x] = i
    return []
# O(N) памяти – классический размен памяти на время
```

### O(N·M) и O(V + E)

```python
def lcs(text1, text2):
    n, m = len(text1), len(text2)
    dp = [[0] * (m + 1) for _ in range(n + 1)]    # (N+1)×(M+1)
    ...
# O(N·M) памяти


def build_graph(edges):
    graph = defaultdict(list)          # V ключей, суммарно E значений
    for u, v in edges:
        graph[u].append(v)
        graph[v].append(u)
    return graph
# O(V + E) памяти
```

## Приёмы снижения памяти

Шесть приёмов, покрывающих почти все задачи на «сделай за O(1) памяти».

### Два указателя вместо копий

Вместо того чтобы создавать новые массивы, двигай индексы по существующему.

```python
# O(N) памяти
def is_palindrome(s):
    clean = [c.lower() for c in s if c.isalnum()]
    return clean == clean[::-1]

# O(1) памяти
def is_palindrome(s):
    lo, hi = 0, len(s) - 1
    while lo < hi:
        while lo < hi and not s[lo].isalnum():
            lo += 1
        while lo < hi and not s[hi].isalnum():
            hi -= 1
        if s[lo].lower() != s[hi].lower():
            return False
        lo += 1
        hi -= 1
    return True
```

### Модификация входа на месте

Если разрешено портить вход, можно вообще не выделять память.

```python
# Убрать все вхождения val, вернуть новую длину. O(1) памяти
def remove_element(arr, val):
    slow = 0
    for fast in range(len(arr)):
        if arr[fast] != val:
            arr[slow] = arr[fast]
            slow += 1
    return slow
```

Тот же приём – пометки прямо во входных данных: в задаче Number of Islands мы пишем
`grid[r][c] = '0'` вместо отдельного множества `visited`. Экономия O(N·M) памяти.

**Обязательно спроси на собеседовании:** *«можно ли модифицировать входные данные?»*.
Если нельзя – придётся платить памятью, и это надо озвучить.

### Скользящий массив в ДП

Самый ценный приём этого раздела. Если для вычисления `dp[i]` нужны только последние
несколько значений, весь массив хранить не надо.

```python
# O(N) памяти
def rob(nums):
    dp = [0] * len(nums)
    dp[0] = nums[0]
    dp[1] = max(nums[0], nums[1])
    for i in range(2, len(nums)):
        dp[i] = max(dp[i - 1], nums[i] + dp[i - 2])
    return dp[-1]

# O(1) памяти – храним только два предыдущих значения
def rob(nums):
    prev2, prev1 = 0, 0
    for x in nums:
        prev2, prev1 = prev1, max(prev1, x + prev2)
    return prev1
```

То же для двумерного ДП: если `dp[i][j]` зависит только от строки `i-1`, храним две строки
вместо всей таблицы – **O(N·M) → O(M)**.

```python
def lcs(text1, text2):
    n, m = len(text1), len(text2)
    prev = [0] * (m + 1)
    for i in range(1, n + 1):
        cur = [0] * (m + 1)
        for j in range(1, m + 1):
            if text1[i - 1] == text2[j - 1]:
                cur[j] = prev[j - 1] + 1
            else:
                cur[j] = max(prev[j], cur[j - 1])
        prev = cur
    return prev[m]
# O(M) вместо O(N·M)
```

Дополнительный трюк: если строки разной длины, разверни цикл так, чтобы хранить более короткую
сторону – получится O(min(N, M)).

**Важная оговорка:** скользящий массив ломает возможность восстановить сам ответ (какие именно
элементы вошли), потому что промежуточные состояния потеряны. Если задача просит не число,
а сам путь или подпоследовательность – придётся хранить всю таблицу. Об этом стоит сказать вслух.

### Битовые маски вместо множеств

Если элементы – это числа из небольшого диапазона (например, 26 букв), состояние можно
упаковать в одно число.

```python
# O(N) памяти
def has_unique_chars(s):
    return len(set(s)) == len(s)

# O(1) памяти – один int как 26 флагов
def has_unique_letters(s):
    mask = 0
    for ch in s:
        bit = 1 << (ord(ch) - ord('a'))
        if mask & bit:
            return False
        mask |= bit
    return True
```

Тот же приём – основа «ДП по подмножествам»: состояние из N ≤ 20 элементов хранится в одном
целом числе.

### Генераторы вместо списков

Если результат нужен один раз и по порядку, не материализуй его.

```python
total = sum([x * 2 for x in arr])     # создаёт список: O(N)
total = sum(x * 2 for x in arr)       # генератор: O(1)

for i, x in enumerate(arr): ...       # enumerate ленивый: O(1)
for a, b in zip(arr1, arr2): ...      # zip ленивый: O(1)
```

Разница – одни скобки. В алгоритмических задачах экономия невелика, но привычка полезная.

### Итеративный обход вместо рекурсии

Убирает стек вызовов и риск `RecursionError`. Для обхода дерева в ширину рекурсия вообще
не нужна – только очередь.

## Размен время – память

Почти любая оптимизация времени – это трата памяти, и наоборот. Уметь назвать этот размен
вслух – признак зрелого кандидата.

| Приём | Время | Память |
|---|---|---|
| Хеш-таблица вместо двойного цикла | O(N²) → O(N) | O(1) → O(N) |
| Мемоизация рекурсии | O(2ᴺ) → O(N) | O(N) на кеш |
| Префиксные суммы | O(N) на запрос → O(1) | O(N) на массив |
| Предварительная сортировка | ускоряет поиск | O(1)…O(N) |
| Два указателя вместо словаря | O(N) → O(N log N) с сортировкой | O(N) → O(1) |
| Скользящий массив в ДП | без изменений | O(N·M) → O(M) |
| Битовая маска вместо set | без изменений | O(N) → O(1) |

Формулировка для собеседования:

> «Здесь классический размен: я плачу O(N) памяти под словарь и получаю взамен O(N) времени
> вместо O(N²). Если память критична, есть альтернатива через сортировку и два указателя –
> это O(N log N) времени, но O(1) памяти.»

Предложить **оба варианта и их размен** – сильнее, чем просто выдать оптимальное по времени
решение.

## Ловушки

**Ловушка 1. Срез считается бесплатным**

```python
for i in range(n):
    sub = arr[i:]        # O(N) памяти и времени на каждой итерации
```
Срез всегда копирует. Внутри цикла это почти всегда ошибка.

**Ловушка 2. Рекурсия «без памяти»**

```python
def sum_list(arr, i=0):
    if i == len(arr):
        return 0
    return arr[i] + sum_list(arr, i + 1)
# выглядит как O(1), на деле O(N) на стек
```

**Ловушка 3. Мемоизация без границ**

```python
@lru_cache(maxsize=None)
def solve(i, j, k, mask): ...
# кеш растёт как произведение диапазонов всех аргументов
```
Чем больше параметров в состоянии, тем больше памяти. Если состояние получилось из четырёх
параметров – скорее всего его можно сузить.

**Ловушка 4. Забыть про память под результат в backtracking**

Все подмножества массива из N элементов – это 2ᴺ списков. Память экспоненциальная, и это надо
назвать явно.

**Ловушка 5. `list(range(n))` вместо `range(n)`**

```python
for i in list(range(10**7)):   # 400 МБ
for i in range(10**7):         # O(1), range ленивый
```

**Ловушка 6. Строки накапливаются копиями**

```python
s = ""
for word in words:
    s += word      # каждая итерация создаёт новую строку
```
Здесь страдает и время (O(суммы²)), и пиковая память. Правильно – `"".join(...)`.

## Проверь себя

Определи дополнительную память каждого фрагмента.

```python
# A
def a(arr):
    total = 0
    for x in arr:
        total += x
    return total

# B
def b(arr):
    return sorted(arr)

# C
def c(n):
    if n == 0:
        return 0
    return n + c(n - 1)

# D
def d(root):
    from collections import deque
    q = deque([root])
    out = []
    while q:
        node = q.popleft()
        out.append(node.val)
        if node.left:  q.append(node.left)
        if node.right: q.append(node.right)
    return out

# E
def e(text1, text2):
    n, m = len(text1), len(text2)
    dp = [[0] * (m + 1) for _ in range(n + 1)]
    return dp

# F
def f(s):
    lo, hi = 0, len(s) - 1
    while lo < hi:
        if s[lo] != s[hi]:
            return False
        lo += 1
        hi -= 1
    return True

# G
def g(arr):
    result = []
    for i in range(len(arr)):
        result.append(arr[i:])
    return result

# H
def h(node):
    if not node:
        return 0
    return 1 + max(h(node.left), h(node.right))
```

<details>
<summary>Ответы</summary>

**A → O(1).** Одна переменная, ничего не создаётся.

**B → O(N).** `sorted()` возвращает новый список. Если бы было `arr.sort()`, ответ был бы
«на месте», хотя Timsort и требует до O(N) буфера.

**C → O(N).** Ни одной структуры, но стек рекурсии глубиной N. Плюс на N > 1000 это упадёт
с `RecursionError`.

**D → O(N).** Очередь BFS в худшем случае хранит целый уровень дерева, а самый широкий уровень
содержит до N/2 узлов. Обрати внимание: у BFS память хуже, чем у DFS на сбалансированном дереве
(O(N) против O(log N)) – это частый вопрос на собеседовании.

**E → O(N·M).** Двумерная таблица. Сводится к O(min(N, M)) скользящими строками.

**F → O(1).** Два индекса, никаких копий. Именно поэтому проверка палиндрома двумя указателями
лучше, чем `s == s[::-1]` (последнее – O(N) памяти).

**G → O(N²).** N срезов, суммарная длина N + (N−1) + … + 1 = N²/2.

**H → O(H), от O(log N) до O(N).** Стек рекурсии по высоте дерева.

</details>

Ключевые пункты: **C** (рекурсия – это память), **D** (BFS дороже DFS по памяти),
**G** (срезы копируются).

## Что говорить на собеседовании

**1. Всегда называй память вместе со временем.**
> «O(N) по времени и O(N) по памяти под словарь.»

**2. Уточняй, что память дополнительная.**
> «O(1) дополнительной памяти, не считая массива под ответ.»

**3. Про рекурсию говори про стек.**
> «Дополнительных структур нет, но стек рекурсии – O(H), где H – высота дерева.
> Для сбалансированного это O(log N), в худшем случае O(N).»

**4. Спрашивай разрешение портить вход.**
> «Можно ли модифицировать входной массив? Если да, я сделаю это на месте за O(1) памяти.»

**5. Предлагай размен как выбор, а не как данность.**
> «Есть два варианта: словарь – O(N) времени и O(N) памяти; сортировка с двумя указателями –
> O(N log N) времени, но O(1) памяти. Какой предпочтительнее в вашем контексте?»

Последний пункт особенно ценен. Он превращает монолог в диалог и показывает, что ты думаешь
про инженерные компромиссы, а не просто вспоминаешь заученное решение.

## Карточки

### Q: Чем дополнительная память отличается от полной и какую имеют в виду по умолчанию?

Полная – это вход плюс всё созданное алгоритмом, дополнительная – только созданное алгоритмом.
Когда говорят «сложность по памяти», почти всегда имеют в виду дополнительную: входные данные
уже существуют. Правильная формулировка на собеседовании – «O(1) дополнительной памяти»,
слово «дополнительной» снимает двусмысленность.

### Q: Считать ли память под возвращаемый результат?

Обычно нет: если задача просит вернуть список из N элементов, эти O(N) неизбежны по условию.
Стандартная формулировка – «O(1) дополнительно, не считая память под ответ». Исключение –
backtracking, где размер ответа может быть экспоненциальным (2ᴺ подмножеств), и это надо
назвать явно.

### Q: Почему рекурсия стоит памяти, даже если внутри ничего не создаётся?

Каждый незавершённый вызов хранит в стеке свои локальные переменные, аргументы и точку
возврата. Пока рекурсия не схлопнулась, все кадры лежат в памяти одновременно, поэтому память
равна максимальной глубине рекурсии. Простой `countdown(n)` без единой структуры данных
стоит O(N) – код выглядит как O(1), а на деле нет.

### Q: Какая память у рекурсивного обхода дерева?

O(H), где H – высота дерева, а не число узлов. Для сбалансированного дерева H ≈ log N,
то есть O(log N); для вырожденного дерева-«палки» H = N, то есть O(N). Полный ответ на
собеседовании звучит именно так: «O(H) на стек; для сбалансированного O(log N), в худшем O(N)».

### Q: Почему BFS дороже DFS по памяти на дереве?

BFS хранит в очереди целый уровень, а самый широкий уровень бинарного дерева содержит до N/2
узлов – это O(N). DFS хранит только текущий путь от корня, то есть O(H), что для
сбалансированного дерева всего O(log N). На вырожденном дереве картина обратная: DFS
деградирует до O(N), а очередь BFS остаётся короткой.

### Q: Какие операции Python незаметно выделяют память?

Срез `arr[i:j]` – всегда копия O(j−i); `sorted(arr)` – новый список O(N); `arr[::-1]` – копия;
`list(d.keys())` – копия ключей; `"".join(parts)` – новая строка. Отдельно: `list.sort()`
не создаёт нового списка, но Timsort внутри требует до O(N) вспомогательного буфера.

### Q: Что такое скользящий массив в ДП и чем за него платят?

Если `dp[i]` зависит только от нескольких предыдущих значений, весь массив хранить не нужно:
для одномерного ДП хватает двух переменных (O(N) → O(1)), для двумерного – двух строк
(O(N·M) → O(M)). Плата: промежуточные состояния потеряны, поэтому восстановить сам ответ
(какие элементы вошли, какой путь) уже нельзя – только итоговое число.

### Q: Как свести память к O(1) в задаче на палиндром или удаление элементов?

Двумя указателями по существующему массиву вместо создания копий: `s == s[::-1]` стоит O(N)
памяти, а два индекса навстречу друг другу – O(1). Второй приём – модификация входа на месте
(быстрый и медленный указатель в remove_element, пометки прямо в grid вместо множества
visited). Перед этим обязательно спроси, можно ли портить вход.

### Q: Что такое битовая маска и когда она заменяет множество?

Упаковка состояния в биты одного целого числа: если элементы из небольшого диапазона
(26 букв, N ≤ 20 предметов), каждый бит – флаг «есть или нет». Множество на O(N) превращается
в один `int`, то есть O(1). Тот же приём лежит в основе ДП по подмножествам, где состояние
из N ≤ 20 элементов хранится одним числом.

### Q: Сколько реально весит список из миллиона чисел в Python?

Около 40 МБ, а не 8 МБ: Python хранит указатели по 8 байт плюс сами объекты `int` по 28 байт,
итого порядка 36 байт на элемент. Множество и словарь – примерно 33 и 37 байт на элемент сверх
объектов. Практическая граница: 10⁷ элементов в списке это уже около 400 МБ, близко к лимиту
большинства проверяющих систем.

### Q: Назови типичные размены время-память.

Хеш-таблица вместо двойного цикла: время O(N²) → O(N), память O(1) → O(N). Мемоизация:
время O(2ᴺ) → O(N), память O(N) на кеш. Префиксные суммы: запрос O(N) → O(1), память O(N).
Обратный размен – сортировка с двумя указателями вместо словаря: время O(N) → O(N log N),
зато память O(N) → O(1). Предлагать оба варианта сильнее, чем выдавать один.
