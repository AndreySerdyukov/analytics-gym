## Что ты будешь уметь после этого урока

- понимать, что происходит при `b = a` и почему это не копия;
- различать изменяемые и неизменяемые типы и предсказывать поведение кода;
- объяснять, почему список нельзя положить в множество;
- находить причину бага по симптому, а не методом тыка.

Это самый «невидимый» урок курса. Он не про алгоритмы – он про то, как Python обращается
с объектами. Но именно здесь рождаются баги, из-за которых правильное по идее решение выдаёт
неправильный ответ.

Три конкретных места, где это стреляет прямо на собеседовании:

- `result.append(path)` в backtracking – в ответе оказываются пустые списки
- `dp = [[0] * m] * n` – при записи в одну ячейку меняется весь столбец
- `visited.add(node)`, где node это список – падает с `TypeError: unhashable type`

Все три – одна и та же тема. Разберём её один раз и навсегда.

## Переменная – это ярлык, а не коробка

### Главная модель

Многие интуитивно представляют переменную как коробку, в которую положено значение.
В Python это не так.

**Объекты живут в памяти сами по себе. Имя – это бирка, привязанная к объекту.** Присваивание
не копирует объект, оно вешает ещё одну бирку.

```python
a = [1, 2, 3]
b = a              # НЕ копия! Ещё одна бирка на тот же список
b.append(4)
print(a)           # [1, 2, 3, 4]  ← изменился и a
print(a is b)      # True – это буквально один объект
```

Схематично:

```
        ┌───────────────┐
a ─────▶│  [1, 2, 3, 4] │◀───── b
        └───────────────┘
          один объект, две бирки
```

Проверить, один ли это объект, можно через `id()` – уникальный идентификатор объекта в памяти:

```python
a = [1, 2, 3]
b = a
print(id(a) == id(b))    # True

c = [1, 2, 3]
print(id(a) == id(c))    # False – другой объект с таким же содержимым
print(a == c)            # True  – содержимое одинаковое
```

### `==` против `is`

| Оператор | Что сравнивает | Когда использовать |
|---|---|---|
| `==` | **значения** | почти всегда |
| `is` | **идентичность объектов** | только с `None`, `True`, `False` |

Правило: **`is` – только для `x is None`.** Во всех остальных случаях `==`.

```python
if node is None:      # ✅ правильно
if x == 0:            # ✅ правильно
if x is 0:            # ❌ работает случайно, а иногда нет (см. раздел про кеширование)
```

### Динамическая типизация: имя не привязано к типу

В Python тип принадлежит **объекту**, а не имени. Одно и то же имя может по очереди указывать
на объекты разных типов.

```python
x = 42          # x указывает на int
x = "hello"     # теперь на str – это законно
x = [1, 2]      # теперь на list
```

Проверить тип:

```python
type(x)                      # <class 'list'>
isinstance(x, list)          # True
isinstance(x, (int, float))  # True, если x число любого из типов
```

В алгоритмических задачах `isinstance` иногда нужен – например, когда во входных данных
перемешаны числа и вложенные списки (задачи вроде Flatten Nested List Iterator).

## Обзор типов данных

### Скалярные типы

| Тип | Пример | Изменяемый? | Заметки |
|---|---|---|---|
| `int` | `42`, `-7` | нет | неограниченная точность, переполнения не бывает |
| `float` | `3.14` | нет | обычная плавающая точка со всеми её проблемами |
| `bool` | `True` | нет | подкласс `int`: `True == 1`, `False == 0` |
| `str` | `"abc"` | нет | последовательность символов |
| `None` | `None` | нет | единственный объект своего типа |

Два факта, полезных в алгоритмах:

**1. `int` в Python не переполняется.**

```python
2 ** 1000     # честно посчитается
```

Это освобождает от целого класса проблем, которые есть в C++ и Java. На собеседовании стоит
упомянуть: *«в Python переполнения нет, в других языках здесь понадобился бы long или модульная
арифметика»*.

**2. `bool` – это число.** Отсюда полезная идиома:

```python
flags = [True, False, True, True]
sum(flags)                     # 3 – считаем количество True
sum(1 for x in arr if x > 0)   # то же самое явно
```

**Осторожно с `float`:**

```python
0.1 + 0.2 == 0.3               # False!
abs(0.1 + 0.2 - 0.3) < 1e-9    # True – так сравнивают вещественные числа
```

В алгоритмических задачах вещественные числа стараются не использовать. Если задача про деление,
часто лучше работать с дробями или домножить всё на знаменатель.

### Контейнеры

| Тип | Пример | Изменяемый? | Упорядочен? | Дубликаты? |
|---|---|---|---|---|
| `list` | `[1, 2, 3]` | **да** | да | да |
| `tuple` | `(1, 2, 3)` | нет | да | да |
| `str` | `"abc"` | нет | да | да |
| `dict` | `{"a": 1}` | **да** | да (порядок вставки) | ключи уникальны |
| `set` | `{1, 2, 3}` | **да** | **нет** | **нет** |
| `frozenset` | `frozenset([1,2])` | нет | нет | нет |

Подробный разбор, **какая структура под какую задачу**, – в следующем конспекте темы.
Здесь нас интересует только их изменяемость.

## Изменяемые и неизменяемые типы

### Определение

**Неизменяемый (immutable)** объект нельзя изменить после создания. Любая «модификация»
на самом деле создаёт новый объект.

**Изменяемый (mutable)** объект можно менять на месте, и все бирки, привязанные к нему,
увидят изменение.

| Неизменяемые | Изменяемые |
|---|---|
| `int`, `float`, `bool` | `list` |
| `str` | `dict` |
| `tuple` | `set` |
| `frozenset` | `bytearray` |
| `bytes` | пользовательские классы (по умолчанию) |
| `None` | |

**Мнемоника:** изменяемые – это те, у кого есть методы, меняющие объект на месте (`append`,
`add`, `update`, `sort`). У строк и кортежей таких методов нет.

```python
s = "hello"
s.upper()            # вернуло 'HELLO'
print(s)             # 'hello' – исходная строка не тронута
s = s.upper()        # надо присвоить обратно
print(s)             # 'HELLO'

s[0] = 'z'           # TypeError: 'str' object does not support item assignment
```

### Зеркальная ловушка: in-place методы возвращают None

```python
arr = [3, 1, 2]
arr = arr.sort()     # ⚠️ arr стал None!
print(arr)           # None
```

`sort()`, `append()`, `reverse()`, `extend()`, `add()`, `update()` меняют объект **на месте**
и возвращают `None`.

```python
arr = [3, 1, 2]
arr.sort()                 # ✅ меняет arr на месте
arr = sorted([3, 1, 2])    # ✅ возвращает новый список
```

Пары, которые надо различать:

| Меняет на месте, возвращает None | Возвращает новый объект |
|---|---|
| `arr.sort()` | `sorted(arr)` |
| `arr.reverse()` | `reversed(arr)`, `arr[::-1]` |
| `arr.append(x)` | `arr + [x]` |
| `s.add(x)` | `s \| {x}` |

Если код внезапно падает с `'NoneType' object is not iterable` – почти наверняка ты присвоил
результат in-place метода.

### Цена неизменяемости строк

Каждая «модификация» строки создаёт новый объект. В цикле это даёт квадратичную сложность:

```python
s = ""
for word in words:
    s += word          # каждый раз создаётся новая строка
```

Правильно:

```python
s = "".join(words)
```

**Реальный замер** на 30 000 слов:

| Способ | Время |
|---|---|
| `"".join(words)` | 0,8 мс |
| `s += word` в цикле | 1,3 мс |
| `s += word`, когда на строку есть вторая ссылка | **14 300 мс** |

Второе число обманчиво хорошее: CPython умеет оптимизировать `s += word`, если на строку больше
никто не ссылается – он достраивает её на месте. Но эта оптимизация хрупкая. Стоит где-то
сохранить ещё одну ссылку на `s` – и время взлетает в семнадцать тысяч раз, потому что каждая
итерация снова начинает копировать всю строку.

**Вывод:** не полагайся на оптимизацию, которой может не быть. Собирай в список и склеивай
через `join`.

Если нужно менять символы по одному – переведи строку в список:

```python
chars = list(s)
chars[0] = 'z'
s = "".join(chars)
```

## Алиасинг: когда два имени это один объект

Корень большинства багов в этой теме.

### Ловушка 1: `[[0] * m] * n`

```python
grid = [[0] * 3] * 3
grid[0][0] = 1
print(grid)      # [[1,0,0], [1,0,0], [1,0,0]]  ⚠️
```

Что произошло: `[0] * 3` создало **один** список. Умножение внешнего списка на 3 создало три
бирки на **этот же самый** список.

```python
grid = [[0] * 3] * 3
print(grid[0] is grid[1])       # True – буквально один объект
```

Правильно – генератор, создающий новый список на каждой итерации:

```python
grid = [[0] * 3 for _ in range(3)]
print(grid[0] is grid[1])       # False ✅
```

**Это ошибка номер один в задачах на ДП и матрицы.** Правило: **любая двумерная структура
строится только через `for _ in range(...)`.**

Обрати внимание: `[0] * 3` безопасно, потому что `0` неизменяемый. Бирок на ноль может быть
сколько угодно, но изменить сам ноль нельзя.

### Ловушка 2: `path` в backtracking

```python
result = []
def backtrack(path):
    if len(path) == 3:
        result.append(path)       # ⚠️ кладём БИРКУ на изменяемый список
        return
    for x in [1, 2, 3]:
        path.append(x)
        backtrack(path)
        path.pop()

backtrack([])
print(result)   # [[], [], [], ...] – все пустые!
```

Все элементы `result` – это один и тот же список `path`, который к концу работы опустел.
Правильно положить **снимок**:

```python
result.append(path[:])       # срез = поверхностная копия
result.append(list(path))    # то же самое
```

Формулировка для собеседования: **«в ответ кладём копию, потому что path продолжит меняться»**.

### Ловушка 3: изменяемый аргумент по умолчанию

```python
def add_item(x, acc=[]):
    acc.append(x)
    return acc

print(add_item(1))    # [1]
print(add_item(2))    # [1, 2]  ⚠️ не [2]!
```

Значение по умолчанию вычисляется **один раз** при определении функции, а не при каждом вызове.

```python
def add_item(x, acc=None):
    if acc is None:
        acc = []
    acc.append(x)
    return acc
```

Касается `list`, `dict`, `set` – всего изменяемого. Неизменяемые (`0`, `""`, `None`, `()`)
безопасны.

### Ловушка 4: изменение коллекции во время итерации

```python
arr = [1, -1, -2, 3]
for v in arr:
    if v < 0:
        arr.remove(v)
print(arr)     # [1, -2, 3]  ⚠️ -2 не удалился!
```

Итератор ходит по индексам, а `remove` сдвигает элементы влево – один элемент проскакивает.

```python
arr = [x for x in arr if x >= 0]     # ✅ строим новый список
```

Для словаря будет явная ошибка `RuntimeError: dictionary changed size during iteration`.
Если надо удалять по ходу – итерируйся по копии ключей: `for k in list(d):`.

## Копирование: три уровня

```python
import copy

original = [[1, 2], [3, 4]]

# 1. Присваивание – вообще не копия
alias = original

# 2. Поверхностная копия – новый внешний список,
#    но внутренние объекты те же самые
shallow = original[:]
shallow[0].append(99)
print(original)                    # [[1, 2, 99], [3, 4]]  ⚠️ изменился!

# 3. Глубокая копия – рекурсивно копируется всё
original = [[1, 2], [3, 4]]
deep = copy.deepcopy(original)
deep[0].append(99)
print(original)                    # [[1, 2], [3, 4]]  ✅ не тронут
```

Способы поверхностного копирования:

```python
new_list = old_list[:]          # срез
new_list = list(old_list)
new_dict = dict(old_dict)       # или old_dict.copy()
new_set  = set(old_set)
```

**На практике в 95 % случаев хватает поверхностной копии** (`path[:]` в backtracking).
`deepcopy` нужен редко и он медленный – если тянешься к нему, скорее всего задачу можно решить
иначе.

Для плоского списка чисел или строк `[:]` – полноценная копия, потому что элементы неизменяемы.
Проблема возникает только с вложенными изменяемыми объектами.

## Как объекты передаются в функции

Python не «по значению» и не «по ссылке» – он передаёт **бирку на объект**.

```python
def mutate(lst):
    lst.append(1)        # меняем ОБЪЕКТ – снаружи видно

def rebind(lst):
    lst = lst + [1]      # создаём НОВЫЙ объект, вешаем локальную бирку
                         # – снаружи ничего не изменилось

a = []
mutate(a); print(a)      # [1]
b = []
rebind(b); print(b)      # []
```

**Правило:** мутируешь объект (`append`, `[i] = x`, `add`) – видно снаружи. Присваиваешь имени
новый объект – не видно.

Отдельно про `+=`, здесь Python неочевиден:

```python
def f(lst):
    lst += [1]           # для списка += это extend – мутация на месте!

a = []
f(a); print(a)           # [1] – изменилось
```

Для списков `x += y` – **мутация на месте** (эквивалент `extend`), а не `x = x + y`. Для чисел,
строк и кортежей `+=` создаёт новый объект, потому что мутировать их невозможно.

### Что это значит для алгоритмов

**1. Вход можно испортить.** Если пишешь `nums.sort()` внутри решения – исходный массив
вызывающего изменится. На собеседовании проговори: *«я сортирую входной массив на месте;
если это нежелательно, сделаю копию»*.

**2. Приём «пометить посещённое прямо в сетке»** работает именно потому, что список изменяемый.
В Number of Islands мы пишем `grid[r][c] = '0'` вместо отдельного `visited` – и экономим память.
Поэтому надо спросить: *«можно ли модифицировать вход?»*

**3. Аккумулятор можно передавать вниз по рекурсии:**

```python
def collect(node, out):
    if not node: return
    out.append(node.val)      # мутируем общий список
    collect(node.left, out)
    collect(node.right, out)

result = []
collect(root, result)
```

## Области видимости: global и nonlocal

```python
def solve():
    best = 0
    def inner():
        best = best + 1     # ⚠️ UnboundLocalError
    inner()
```

Присваивание внутри функции делает имя **локальным**. Python видит `best = ...`, считает `best`
локальной переменной – и она оказывается не инициализированной.

Два выхода:

```python
# Вариант 1: nonlocal – разрешить переприсваивание внешнего имени
def solve():
    best = 0
    def inner():
        nonlocal best
        best += 1
    inner()
    return best

# Вариант 2: изменяемый контейнер – присваивания нет, есть мутация
def solve():
    best = [0]
    def inner():
        best[0] += 1        # это МУТАЦИЯ списка, а не присваивание имени
    inner()
    return best[0]
```

Второй вариант работает без `nonlocal` именно потому, что мы не переприсваиваем имя, а меняем
объект. Приём встречается в чужом коде часто; сам предпочитай `nonlocal` – он читаемее.

**Важно:** читать внешнюю переменную можно без всяких объявлений. `nonlocal` нужен только
для **присваивания**.

```python
def solve():
    limit = 10
    def inner(x):
        return x < limit     # ✅ чтение работает без nonlocal
```

Именно эта механика стоит за шаблоном из задачи о диаметре дерева:

```python
def diameter_of_binary_tree(root):
    best = 0
    def depth(node):
        nonlocal best        # ← вот зачем это здесь
        ...
```

`global` работает так же, но для переменных уровня модуля. В алгоритмических задачах он почти
не нужен – хватает `nonlocal`.

## Хешируемость: кто может быть ключом

`dict` и `set` кладут элементы по хешу. Хеш должен быть неизменным на протяжении жизни объекта –
иначе элемент «потеряется». Поэтому:

**Хешируемы только неизменяемые объекты.**

```python
d = {}
d[42] = 'a'                  # ✅ int
d["key"] = 'b'               # ✅ str
d[(1, 2)] = 'c'              # ✅ tuple
d[frozenset([1, 2])] = 'd'   # ✅ frozenset

d[[1, 2]] = 'e'              # ❌ TypeError: unhashable type: 'list'
d[{1, 2}] = 'f'              # ❌ TypeError: unhashable type: 'set'
```

Правило: **список → кортеж, множество → frozenset.**

### Практические следствия

**1. Координаты в `visited` – только кортежи:**

```python
visited = set()
visited.add((r, c))          # ✅
# visited.add([r, c])        # ❌
```

Вот почему в BFS по сетке везде `(nr, nc)`, а не `[nr, nc]`.

**2. Ключ группировки – кортеж:**

```python
groups[tuple(sorted(word))].append(word)     # Group Anagrams
```

`sorted()` возвращает список, его надо обернуть в `tuple`.

**3. `@lru_cache` требует хешируемых аргументов:**

```python
from functools import lru_cache

@lru_cache(None)
def solve(items):
    return sum(items)

solve([1, 2])       # ❌ TypeError: unhashable type: 'list'
solve((1, 2))       # ✅ 3
```

Частая проблема при мемоизации ДП. Решение: превратить в кортеж либо передавать индексы вместо
самих данных (это обычно и правильнее – состояние должно быть маленьким).

### Подвох: кортеж не всегда хешируем

Кортеж неизменяем **поверхностно**:

```python
hash((1, 2))          # ✅ работает
hash((1, [2]))        # ❌ TypeError: unhashable type: 'list'

t = ([1, 2], 3)
t[0].append(99)       # ✅ работает! список внутри кортежа изменяем
print(t)              # ([1, 2, 99], 3)
```

Неизменяемость кортежа означает «нельзя заменить элементы кортежа», а не «содержимое элементов
заморожено».

Совсем странный случай, который стоит увидеть один раз:

```python
t = ([1, 2], 3)
t[0] += [99]          # TypeError: 'tuple' object does not support item assignment
print(t)              # ([1, 2, 99], 3)  – но список ВСЁ РАВНО изменился!
```

`+=` для списка сначала выполняет мутацию на месте, а потом пытается присвоить результат обратно
в `t[0]` – и падает уже после того, как список изменён.

## Истинность значений и её ловушки

В условиях можно писать не только сравнения, но и сами объекты. Python сам приводит их
к `True`/`False`.

**Ложными считаются:**

```python
False, None, 0, 0.0, "", [], {}, set(), ()
```

Всё остальное истинно. Отсюда идиомы, которые ты будешь встречать постоянно:

```python
if not node:        # узел None – база рекурсии
if not arr:         # пустой массив
if not stack:       # стек опустел
while queue:        # пока очередь не пуста
```

### Ловушка: 0 и пустая строка тоже ложны

```python
def find_index(arr, x):
    idx = arr.index(x)
    if not idx:              # ⚠️ БАГ: idx == 0 это валидный ответ!
        return "не найдено"
    return idx
```

Ноль – валидный индекс, но `not 0` даёт `True`. Правильно:

```python
if idx is None:              # ✅ явная проверка
if idx == -1:                # ✅ или по договорённости
```

**Правило:** если значение может быть нулём, пустой строкой или пустым списком, и это
осмысленный результат, – проверяй явно через `is None` или `== 0`, а не через `if not x`.

Тот же случай с узлом дерева:

```python
if node.val:          # ⚠️ узел со значением 0 будет считаться отсутствующим
if node is not None:  # ✅
```

### Полезные следствия

```python
x = value or default          # если value ложно, берём default
count = len(arr) or 1         # защита от деления на ноль
result = data if data else [] # явнее, но длиннее
```

Осторожно: `x = value or default` тоже сработает не так, если `value` – валидный ноль.

## Кеширование чисел и почему `is` иногда «работает»

```python
a = 100
b = 100
a is b        # True

a = 1000
b = 1000
a is b        # может быть True, а может False – зависит от контекста
```

CPython заранее создаёт объекты для маленьких целых (примерно от −5 до 256) и переиспользует их.
Плюс компилятор объединяет одинаковые константы внутри одного блока кода. Со строками похоже:
строки, похожие на идентификаторы, «интернируются» при компиляции.

**Практический вывод один: никогда не используй `is` для сравнения значений.** Оно может
случайно сработать на маленьких числах и подвести на больших – классический источник плавающих
багов.

```python
if x is 0:      # ❌ в новых версиях Python ещё и SyntaxWarning
if x == 0:      # ✅
if x is None:   # ✅ единственный правильный случай для is
```

## Чек-лист: «странный баг, что проверить»

| Симптом | Вероятная причина |
|---|---|
| В ответе список пустых или одинаковых списков | забыл `[:]` при `result.append(path)` |
| Изменил ячейку матрицы – поменялся весь столбец | `[[0] * m] * n` вместо генератора |
| `'NoneType' object is not iterable` | присвоил результат `sort()` / `append()` |
| `TypeError: unhashable type: 'list'` | кладёшь список в `set` / `dict` / `lru_cache` |
| Функция «помнит» результат прошлого вызова | изменяемый аргумент по умолчанию |
| `UnboundLocalError` во вложенной функции | нужен `nonlocal` |
| Часть элементов не удалилась из списка | меняешь список во время итерации |
| Ветка кода не срабатывает при нулевом значении | `if not x` там, где 0 – валидное значение |
| Решение верное, но не проходит по времени на строках | конкатенация строк в цикле вместо `join` |
| Второй вызов функции даёт другой ответ | первый вызов испортил входные данные |

## Проверь себя

Предскажи вывод, не запуская.

## Карточки

### Q: Что происходит при `b = a`, если `a` – список?

Присваивание не копирует объект. Оно вешает на тот же самый список вторую бирку, поэтому
`b.append(4)` виден и через `a`, а `a is b` даёт `True`. Копия получается только явно:
`a[:]`, `list(a)` или `copy.deepcopy(a)` для вложенных структур.

### Q: Когда использовать `is`, а когда `==`?

`==` сравнивает значения и нужен почти всегда. `is` сравнивает идентичность объектов, и его
единственное законное применение – `x is None`. На маленьких числах `is` может случайно
сработать из-за кеширования целых от −5 до 256, а на больших подвести – это классический
источник плавающих багов.

### Q: Какие типы в Python изменяемые, а какие нет?

Неизменяемые: `int`, `float`, `bool`, `str`, `tuple`, `frozenset`, `bytes`, `None`.
Изменяемые: `list`, `dict`, `set`, `bytearray`, обычные пользовательские классы. Мнемоника:
изменяемые – те, у кого есть методы, меняющие объект на месте (`append`, `add`, `sort`).

### Q: Почему `[[0] * m] * n` – это баг?

Внутренний `[0] * m` создаёт один список, а умножение внешнего создаёт n бирок на этот же
объект. Запись `grid[0][0] = 1` меняет все строки сразу, и `grid[0] is grid[1]` даёт `True`.
Правильно только через генератор: `[[0] * m for _ in range(n)]`, который создаёт новый список
на каждой итерации.

### Q: Почему в backtracking пишут `result.append(path[:])`, а не `result.append(path)`?

Потому что `path` продолжает меняться после добавления: `append` кладёт бирку на живой объект,
и к концу обхода все элементы `result` указывают на один и тот же опустевший список. Срез
делает снимок текущего состояния. Эквивалент – `list(path)`.

### Q: Что не так с `def f(x, acc=[])`?

Значение по умолчанию вычисляется один раз при определении функции, а не при каждом вызове,
поэтому список накапливает данные между вызовами: `f(1)` даёт `[1]`, а `f(2)` уже `[1, 2]`.
Правильно `acc=None` и `if acc is None: acc = []`. Неизменяемые дефолты (`0`, `""`, `()`)
безопасны.

### Q: Чем отличается поверхностная копия от глубокой?

Поверхностная (`arr[:]`, `list(arr)`, `dict(d)`) создаёт новый внешний контейнер, но внутренние
объекты остаются общими – изменение вложенного списка видно в обеих копиях. `copy.deepcopy`
копирует рекурсивно. На практике в 95 % случаев хватает поверхностной; для плоского списка
чисел она вообще полноценная, потому что элементы неизменяемы.

### Q: Почему `arr = arr.sort()` обнуляет массив?

`sort()` меняет список на месте и возвращает `None`, поэтому присваивание записывает в имя
`None`. То же с `append`, `reverse`, `extend`, `add`, `update`. Новый объект возвращают их пары:
`sorted(arr)`, `reversed(arr)`, `arr + [x]`. Симптом ошибки – `'NoneType' object is not iterable`.

### Q: Чем `lst += [1]` отличается от `lst = lst + [1]` внутри функции?

Для списка `+=` это мутация на месте (эквивалент `extend`), поэтому изменение видно снаружи
функции. `lst = lst + [1]` создаёт новый объект и перепривязывает локальное имя – снаружи ничего
не меняется. Для чисел, строк и кортежей `+=` всегда создаёт новый объект, мутировать их нельзя.

### Q: Какие объекты можно класть в `set` и использовать ключом `dict`?

Только хешируемые, то есть неизменяемые: числа, строки, кортежи, `frozenset`. Хеш обязан быть
неизменным всю жизнь объекта, иначе элемент потеряется в таблице. Отсюда практика: координаты
в `visited` кладут кортежами `(r, c)`, ключ группировки анаграмм – `tuple(sorted(word))`,
а `@lru_cache` не принимает списки в аргументах.

### Q: Кортеж всегда хешируем?

Нет. Неизменяемость кортежа поверхностная: `hash((1, 2))` работает, а `hash((1, [2]))` падает,
потому что внутри изменяемый список. Более того, `t[0].append(99)` для `t = ([1, 2], 3)`
отработает штатно – нельзя заменить элементы кортежа, но содержимое элементов не заморожено.

### Q: Зачем нужен `nonlocal` и когда он не нужен?

Присваивание внутри функции делает имя локальным, поэтому `best = best + 1` во вложенной функции
падает с `UnboundLocalError`. `nonlocal best` разрешает переприсваивать имя из внешней области.
Для **чтения** внешней переменной ничего объявлять не нужно. Альтернатива без `nonlocal` –
изменяемый контейнер `best = [0]` и мутация `best[0] += 1`, но `nonlocal` читаемее.

### Q: Какие значения в Python считаются ложными и где это стреляет?

`False`, `None`, `0`, `0.0`, `""`, `[]`, `{}`, `set()`, `()`. Ловушка: ноль – валидный индекс
и валидное значение узла, поэтому `if not idx` и `if node.val` ломаются на нуле. Если значение
может быть нулём или пустым и это осмысленный результат, проверяй явно: `is None` или `== 0`.
