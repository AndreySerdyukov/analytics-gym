# PRD — analytics-gym

Что приложение делает с точки зрения поведения. Технические конвенции — в [`CLAUDE.md`](CLAUDE.md).

## Проблема
Задачи с собеседований и теория по DA/DS не собраны в одном месте: часть в голове, часть в
закладках. Повторять нечего, прогресс не виден, SQL-задачи решаются «на глаз» без проверки.

## Пользователь
Один человек — владелец репозитория. Готовится к собеседованиям на Data Analyst / Data Scientist,
пополняет базу задач сам, занимается регулярно короткими сессиями.

## Ключевые сценарии

### 1. Записать задачу, которая встретилась
Задача создаётся командой `new-task`, дописывается в редакторе, проверяется `validate` и попадает
в приложение после `sync`. Трение минимальное: не нужно открывать UI и заполнять форму.

### 2. Порешать SQL с автопроверкой
Открыть блок SQL, отфильтровать по сложности или теме, открыть задачу, написать запрос, запустить.
Приложение выполняет запрос пользователя и эталон на одном датасете и сравнивает результаты.
При расхождении показывает, чем результаты отличаются, а не просто «неверно».

### 3. Повторить теорию
На главной видно, сколько карточек к повторению сегодня. Режим `/review` показывает вопрос,
по кнопке — ответ, дальше самооценка (забыл / с трудом / легко). Алгоритм SM-2 назначает
следующую дату показа.

### 4. Понять, где слабые места
Статистика показывает решаемость по блокам и тегам, среднее время, историю занятий.

## Требования по блокам

### Блоки и навигация
- Блоки первой версии: `sql`, `stats-ab`, `python`, `ml`. Набор задаётся в `content/blocks.yaml`,
  добавление нового блока не требует изменений кода.
- Переключение между блоками доступно с любой страницы.
- Внутри блока задачи группируются по темам (`topic`).

### Задачи
- Поля: заголовок, блок, тема, сложность (`easy|medium|hard`), теги, источник
  (`interview|course|leetcode|own`), компания, оценка времени, датасет, настройки проверки.
- Разделы: условие, эталонное решение, разбор.
- Решение и разбор по умолчанию скрыты и раскрываются явным действием.
- Статусы: `new` → `in_progress` (была хотя бы одна попытка) → `solved` (была верная попытка).
  Статус `failed` выставляется вручную пользователем, если он сдался.
- К задаче можно написать личную заметку. Она хранится только в БД и не попадает в репозиторий.

### SQL-раннер
- Движок — PGlite (Postgres в WASM), выполняется в браузере, в воркере.
- Перед каждой задачей схема сбрасывается и заново накатывается датасет: результат не зависит
  от предыдущих запусков и от того, что пользователь выполнял `DROP TABLE`.
- Запрос пользователя выполняется в транзакции с откатом: `INSERT`/`UPDATE`/`DROP` в запросе не
  портят датасет для следующей попытки.
- Ограничения: таймаут выполнения (по умолчанию 10 секунд, воркер убивается), лимит отображаемых
  строк (по умолчанию 200, с пометкой об усечении).
- Ошибка Postgres показывается как есть — это часть обучения.

### Сравнение результатов
- Ожидаемый результат не хранится: эталонный SQL выполняется на том же датасете при каждой проверке.
- Настройки в блоке `check` задачи:
  - `ordered` (по умолчанию `false`) — если `false`, строки сравниваются как мультимножество;
  - `tolerance` (по умолчанию `0.001`) — допуск при сравнении чисел;
  - `ignore_column_names` (по умолчанию `true`) — сравнивать по позициям колонок, а не по именам.
- Edge cases: разное число колонок → «ожидалось N колонок, получено M»; разное число строк →
  показать сколько лишних и недостающих; `NULL` считается равным `NULL`; числовые типы
  сравниваются как числа независимо от того, вернулись они как `numeric` или `float`.

### Повторение (SM-2)
- Карточки берутся из раздела `## Карточки` конспектов теории.
- Оценки: `0` забыл, `3` с трудом, `5` легко.
- Первый интервал 1 день, второй 6 дней, дальше умножается на ease factor (минимум 1.3).
- Оценка ниже 3 сбрасывает счётчик повторений, интервал возвращается к 1 дню.
- К повторению сегодня = карточки с `due_date <= сегодня` плюс никогда не показанные.
- Edge case: если карточка удалена из контента, её история повторений сохраняется, но карточка
  больше не показывается.

### Статистика
- Решаемость по блокам и по тегам, среднее время решения, серия занятий, heatmap активности.
- Считается по `attempts` и `review_logs`, то есть по реальным действиям, а не по самооценке.

## Маршруты

| Маршрут | Что показывает |
|---|---|
| `/` | Дашборд: блоки с прогрессом и незаконченные задачи |
| `/b/:blockSlug` | Список задач блока с фильтрами и поиском |
| `/t/:taskSlug` | Задача: условие, схема данных, редактор, решение, разбор, заметка |

Слаг задачи глобально уникален и включает блок (`sql-retention-d7`), поэтому блок в адресе
задачи не дублируется.

## Режим публичного демо
Тот же интерфейс, собранный статически для GitHub Pages:
- контент читается из сгенерированного `content.json`;
- прогресс, попытки и SRS хранятся в `localStorage` браузера посетителя;
- SQL-раннер работает полностью (он и так в браузере);
- личные заметки в демо не публикуются;
- маршруты живут в хеше (`/#/t/slug`): Pages отдаёт только статику и не умеет возвращать
  `index.html` на произвольный путь.

## Acceptance criteria первой версии (этапы 0–3)
- [ ] `docker compose up -d db && alembic upgrade head && python -m tools sync` наполняет БД из `content/`
- [ ] `python -m tools validate` падает с понятной ошибкой, если эталонный SQL не выполняется
- [ ] На главной видны 4 блока с числом задач и прогрессом
- [ ] В блоке SQL работают фильтры по сложности, тегу, статусу и текстовый поиск
- [ ] На странице задачи можно выполнить запрос и получить результат из PGlite
- [ ] Неверный ответ показывает содержательное расхождение, верный — отмечает задачу решённой
- [ ] Статус и время сохраняются после перезагрузки страницы
- [ ] Светлая и тёмная темы читаемы, выбор темы сохраняется
